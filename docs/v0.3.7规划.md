## 一、要解决的问题

v0.3.6 在重做内嵌 dsh 窗口标题栏时，**引入了一条越权路径**：

```
dsh 页面（remote 上下文 http://127.0.0.1:*，内含用户从推荐页安装的第三方插件代码）
  │ topbar.js:20  emit('topbar-ctrl', { action: action, version: VER })
  │   ← 应用自有命令被 ACL 拒绝，但 event 插件由 core:default 覆盖，可用
  ▼
Tauri 事件总线（任何 remote 页面都能 emit）
  │ lib.rs:540  app.listen_any("topbar-ctrl", move |event| { ... })
  ▼
lib.rs:455-458   let version = v.get("version").and_then(|a| a.as_str()).unwrap_or("");
                let label = { lock_procs(&procs).get(version).map(...) };
                match action { "minimize" => win.minimize(), "close" => win.close(), ... }
```

**三个具体风险**：

1. **越权**：`version` 由页面自己填。页面内任何代码（**包括用户安装的第三方 dsh 插件**）都能关掉**别的版本**的窗口。`topbar-restart` 同理，可重启任意版本。
2. **无类型**：`serde_json::Value` 逐字段手取，字段改名编译期不报错。已补的 `topbar_script_emits_events_matching_rust_listeners`（`95ddbad`）只校验**事件名**，不校验 payload 形状。
3. **权限面被迫放大**：v0.3.5 的 capability 有 3 条权限，v0.3.6 变成 **10 条**（新增 7 条 `core:window:*`），且 `windows: ["main", "dsh-*"]` 不变、`csp: null` 不变。结果：**加载第三方 Web 内容的窗口同时拥有事件、`opener`、`dialog`、窗口三键**。

**为什么 v0.3.7 必须单独发布**：v0.3.6 是两天前刚发布的，这条路径在 v0.3.5 时**不存在**。不单独发，越权窗口会开到 v0.4.0 发布时（约 9–12 周后），正好覆盖最不该叠加的大改动期。

### 3.2 A1：内嵌窗口事件监听按窗口绑定

**现状**：`lib.rs:502/519/540/569` 四个 `app.listen_any`，监听所有窗口的 emit，用 payload 里的 `version` 字段反查 label。

**改法**：建窗口时用 `window.listen(...)` 绑定该窗口，闭包直接捕获真实版本号。

**关键改动点**（`launch.rs:98` 的 `WebviewWindowBuilder` 之后）：

```rust
// 现状（lib.rs 内全局）：
app.listen_any("topbar-ctrl", move |event| {
    let version = v.get("version").and_then(|a| a.as_str()).unwrap_or("");
    // 用 payload 的 version 反查 label —— 任意页面可伪造
});

// 改法（launch_window 内，只监听该窗口）：
let version_for_listen = version.clone();
window.listen("topbar-ctrl", move |event| {
    // 版本号已由闭包捕获，payload 里的 version 忽略（或只做一致性校验）
    let action = v.get("action").and_then(|a| a.as_str()).unwrap_or("");
    match action {
        "minimize" => { let _ = window.minimize(); }
        "toggle-maximize" => { ... }
        "close" => { let _ = window.close(); }
        _ => {}
    }
});
```

**四个事件全部改**：`topbar-log`（写日志）、`topbar-restart`（调 `restart_version_impl`）、`topbar-ctrl`（三键）、`topbar-theme`（`set_dwm_dark`）。

**注意**：`window.listen` 的闭包需 `move`，捕获 `window.clone()`（或 `window.as_ref()` 的 `WebviewWindow`）与 `version.clone()`。`restart_version_impl` 需 `AppHandle` + `ProcMap`，闭包捕获 `app.clone()` + `procs.clone()`。

**实施补强（2026-11-09）**：实测发现仅靠 `window.listen` 不够——Tauri 的全局 `emit` 会送达所有窗口的监听器。最终实现同时采用：

- topbar 改用 `plugin:event|emit_to` 定向当前窗口 label；
- 每窗口注入随机 128-bit token，Rust 监听器校验 token；
- 闭包捕获真实版本号，payload 的 `version` 完全忽略。

这样即使页面伪造 target 或改写 `metadata.currentWindow.label`，也无法通过其他窗口的 token 校验。

**验收**：

打开两个版本的窗口，在版本 A 的 dsh 页面控制台执行：

```js
emit('topbar-ctrl', {action:'close', version:'<版本B>'})
```

**版本 B 的窗口不应关闭。** 这是越权是否真正堵住的最直接验证。

### 3.3 A2：capability 拆两份

**现状**：`src-tauri/capabilities/default.json`（28 行）—— 一份 capability 同时覆盖 `main` 与 `dsh-*` 窗口，10 条权限全部给到两边。

**改法**：拆成两份：

`src-tauri/capabilities/main.json`：

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "main",
  "description": "Capability for the main manager window",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "opener:default",
    "dialog:default",
    "core:window:allow-start-dragging",
    "core:window:allow-minimize",
    "core:window:allow-toggle-maximize",
    "core:window:allow-maximize",
    "core:window:allow-unmaximize",
    "core:window:allow-is-maximized",
    "core:window:allow-close"
  ]
}
```

`src-tauri/capabilities/dsh.json`：

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "dsh",
  "description": "Capability for embedded dsh windows",
  "windows": ["dsh-*"],
  "remote": {
    "urls": [
      "http://127.0.0.1:*",
      "http://localhost:*"
    ]
  },
  "permissions": [
    "core:window:allow-start-dragging",
    "core:window:allow-minimize",
    "core:window:allow-toggle-maximize",
    "core:window:allow-maximize",
    "core:window:allow-unmaximize",
    "core:window:allow-is-maximized",
    "core:window:allow-close"
  ]
}
```

**关键点**：

- **实施结果（2026-11-09）**：`dsh.json` 仅保留 `core:event:allow-emit-to` 与 `core:window:allow-start-dragging`。
  - 三键/重启/主题由 Rust 侧处理，不需要给页面 JS 窗口权限；拖拽仍需 start-dragging。
  - topbar 使用 `emit_to`，因此授权 `allow-emit-to`，不再授权全局 `allow-emit`。
  - `core:default` / `opener` / `dialog` 全部移除。

**风险**：A2 可能触发内嵌窗口的隐藏 IPC 依赖，需能单独回滚（这就是为什么 A1 与 A2 分开 PR）。

### 3.4 A3：`LaunchIntent` 合并三个 static

**现状**（`lib.rs:62-90`）：

```rust
pub(crate) static LAUNCH_MODE: Mutex<Option<String>>    = Mutex::new(None);   // --launch-version 的值
pub(crate) static LAUNCH_ERROR: Mutex<Option<String>>   = Mutex::new(None);   // 启动错误
pub(crate) static OPEN_SETTINGS: Mutex<Option<String>>  = Mutex::new(None);   // --open-settings 的值
```

三个 `Mutex<Option<String>>` + 三个 lock 函数（`lock_launch_mode` / `lock_launch_error` / `lock_open_settings`）。

**改法**：

```rust
pub(crate) struct LaunchIntent {
    pub mode: Option<String>,        // --launch-version
    pub error: Option<String>,       // 启动错误
    pub open_settings: Option<String>, // --open-settings
}

pub(crate) static LAUNCH_INTENT: Mutex<LaunchIntent> = Mutex::new(LaunchIntent {
    mode: None,
    error: None,
    open_settings: None,
});

pub(crate) fn lock_launch_intent() -> MutexGuard<'static, LaunchIntent> {
    LAUNCH_INTENT.lock().unwrap_or_else(|e| e.into_inner())
}
```

**改动点**（全在 `lib.rs`）：
- 定义：3 行 static → 1 个 struct + 1 个 static
- 三个 lock 函数 → 1 个
- 调用点：`lib.rs:212/214/296/319/320/376/405` 全部改为 `lock_launch_intent().mode = ...`

**行为零变化**：三个字段的写入时机、读取时机、语义完全不变，只是从三个锁变成一个锁。

**验收**：`cargo test --lib` 全绿（201 passed / 1 ignored），`launch.rs` 里对三个 static 的引用全部编译通过。

### 3.5 A4：i18n key 校验

**现状**：5 个语言文件（`zh-CN` / `zh-TW` / `en-US` / `ja-JP` / `ko-KR`）**各 361 key，数量一致**（刚实测）。但**没有自动化校验**——未来改文案时可能只改一种语言，导致 key 缺失。

**改法**：新增 `scripts/check-i18n.mjs`：

```js
#!/usr/bin/env node
// 以 zh-CN 为基准，检查其他 4 个语言文件的 key 是否齐全
import { resolve, dirname } from "node:path";
import { fileURLToPath } from "node:url";

const __dirname = dirname(fileURLToPath(import.meta.url));
const base = resolve(__dirname, "../src/composables/i18n");

const LANGS = ["zh-CN", "zh-TW", "en-US", "ja-JP", "ko-KR"];
const REF = "zh-CN";

function flatten(obj, prefix = "") {
  const out = [];
  for (const k of Object.keys(obj)) {
    const v = obj[k];
    if (typeof v === "object" && v !== null && !Array.isArray(v)) {
      out.push(...flatten(v, prefix + k + "."));
    } else {
      out.push(prefix + k);
    }
  }
  return out;
}

async function loadKeys(lang) {
  const m = await import(resolve(base, lang + ".js"));
  return new Set(flatten(m.default));
}

const refKeys = await loadKeys(REF);
console.log(`${REF}: ${refKeys.size} keys`);

let failed = false;
for (const lang of LANGS) {
  if (lang === REF) continue;
  const keys = await loadKeys(lang);
  const missing = [...refKeys].filter((k) => !keys.has(k));
  const extra = [...keys].filter((k) => !refKeys.has(k));
  if (missing.length || extra.length) {
    failed = true;
    console.error(`\n✗ ${lang}: 缺 ${missing.length} 个，多 ${extra.length} 个`);
    if (missing.length) console.error("  缺失:", missing.slice(0, 10).join(", ") + (missing.length > 10 ? " ..." : ""));
    if (extra.length) console.error("  多余:", extra.slice(0, 10).join(", ") + (extra.length > 10 ? " ..." : ""));
  } else {
    console.log(`✓ ${lang}: ${keys.size} keys`);
  }
}

if (failed) process.exit(1);
```

**CI 加一行**（`.github/workflows/ci.yml` 的 `Frontend build` 之后）：

```yaml
      - name: i18n key check
        run: node scripts/check-i18n.mjs
```

**验收**：本地 `node scripts/check-i18n.mjs` 输出 5 个语言各 361 keys 全绿；CI 通过。

### 3.6 A5：契约测试

**现状**：`src-tauri/tests/` **目录不存在**——所有测试都在 `src/` 内的 `#[cfg(test)]` 模块里。`updater.rs` 有 1 个 `#[ignore]` 的真实网络测试。

**改法**：新建 `src-tauri/tests/contracts/` 目录 + 在 `Cargo.toml` 加 `[[test]]` 声明：

```toml
[[test]]
name = "contracts"
path = "tests/contracts/mod.rs"
harness = false
```

**测试内容**：

1. **`PnpmRunner` fake 对拍**：用 fake 的 pnpm 输出（模拟成功 / 失败 / 超时）驱动 `InstallService`，验证解析器行为
2. **真实 pnpm 输出对拍**：调一次 `pnpm view <pkg>` 拿真实输出，验证解析器能正确提取版本号（`#[ignore]`，不进主 CI）
3. **真实 GBK 字节解码**：用一段 GBK 编码的中文错误输出，验证 `console_decode` 能正确转 UTF-8（`#[ignore]`）

**独立 job**（`.github/workflows/ci.yml` 新增）：

```yaml
  contracts:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - uses: Swatinem/rust-cache@v2
        with:
          workspaces: src-tauri
      - name: Contract tests (ignored)
        run: cargo test --manifest-path src-tauri/Cargo.toml --test contracts -- --ignored
```

**为什么放这里而不是 alpha 周期**：

- 契约测试的价值在「发现外部世界的变化」，而 alpha.2 正是要动外部调用（`PnpmRunner` 端口、`DshLauncher` 端口）
- **在动端口之前建立契约测试，等于给端口改造买了保险**——改造时一旦行为偏移，契约测试立刻报警
- 反过来，如果先改端口再写契约测试，等于先拆了地基再测房子

**代价**：v0.3.7 从 5 人日涨到 5–7 人日。这 2 人日值得。

### 3.7 A6：staged 自更新失败路径用例

**现状**：`staged.rs` 有 8 个公开函数（`stage_dir` / `staged_exe` / `pending_path` / `load_pending` / `save_pending` / `clear_stage` / `cleanup_backup` / `take_over_pending`），但**没有任何测试**。

**改法**：新建 `src-tauri/tests/staged_failures.rs`，覆盖三个失败场景：

1. **磁盘满**：目标分区剩余空间 < 新 exe 大小时，`take_over_pending` 应返回错误且旧 exe 仍可启动
2. **杀软拦截**：`rename` 失败时（模拟为返回 `PermissionDenied`），旧 exe 应保留
3. **目标被占用**：旧 exe 正在运行时 `rename` 失败，应返回明确错误

**验收**：`cargo test --test staged_failures` 通过；模拟失败路径时旧 exe 仍可启动。

## 十、开始的第一步

**从 A1 开始，不要从 alpha.1 开始。**

理由：

1. A1 只改 `launch_window` 一处 + 删 4 个 `listen_any`，**半天可完成**
2. 它消掉的是**越权风险**，不是债——拖到 v0.4.0 意味着这个风险窗口再开 9–12 周
3. 它是 v0.3.7 的探路石：如果 A1 改完发现内嵌窗口有意外依赖（例如某个 IPC 调用藏在 `topbar.js` 深处），可以在 v0.3.7 内消化，而不是在 alpha 周期的大改动中暴露

**A1 完成后的验收（最直接）**：

打开两个版本的窗口，在版本 A 的 dsh 页面控制台执行：

```js
emit('topbar-ctrl', {action:'close', version:'<版本B>'})
```

**版本 B 的窗口不应关闭。** 这是越权是否真正堵住的最直接验证。
