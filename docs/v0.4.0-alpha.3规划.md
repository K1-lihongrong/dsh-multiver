## 一、为什么做这一轮

alpha.2 已把类型、配置和部分 Job 基础落地，但仍有两条风险没有收口：

1. 一键更新在替换 exe 后可能退出而不重启，用户再次打开仍是旧版。
2. dsh adapter 和 Job 事件还没有统一，扫描、启动、安装、插件操作的事件字段和取消路径仍分散。

前者是用户可见的发布链路问题，后者是后续实例 UI 和插件能力扩展的前置技术债。alpha.3 的目标是把这两类问题收口，并通过兼容矩阵回归确认没有破坏插件安装、启动和协议行为。

## 二、目标与边界

### 2.1 本轮目标

- 更新替换不依赖外部管道探测进程，不会卡死。
- 替换失败可以回滚，旧 exe 保持可启动。
- 更新成功后自动重启，不需要用户手动打开第二次。
- DSH 版本差异通过 adapter 表达，未知版本不走新版本专属能力。
- Job 有稳定 id、类型、目标、开始时间、状态和取消 token。
- 新代码继续发送 `job:*` 事件，同时保留旧事件兼容。
- 扫描可以同时通过旧全局标记和 Job token 取消。
- 兼容矩阵按隔离 `DSH_HOME` 重新跑通。

### 2.2 明确不做

- 不做 v0.4.0 的实例 UI 重设计。
- 不新增插件市场、下载源或跨版本聚合能力。
- 不改变现有命令签名、JSON 字段和用户可见插件操作流程。
- 不在用户验收前合并 main、打 tag 或推 CI 发布。
- 不把本机事故路径和私有归档写进公开文档。
## 三、工作包

### A3-1 一键更新替换与自动重启

- 在进程内完成 exe 替换：复制临时文件、旧 exe 改名 `.old`、新 exe 改名到目标。
- 替换失败时回滚，保留旧 exe 和可恢复备份。
- 延迟重启脚本不再使用 `tasklist | findstr` 管道。
- 暂存更新安装后立即安排重启。
- 新增更新替换、回滚、重启脚本回归测试。

### A3-2 DSH adapter 拆分与能力门控

- `dsh_adapter` 拆为 `detect` / `v0_1` / `v0_3` / `mod`。
- 统一 CLI 入口、profile 目录和能力查询。
- `allow-version` 仅对支持该能力的版本开放。
- 未知或垃圾版本走 `UnknownAdapter`，不误开新版本专属能力。

### A3-3 JobEventSink 与取消令牌

- Job 快照新增 `started_at`。
- 每个 Job 持有 `CancellationToken`。
- 历史上限 64 条，淘汰时清理 token。
- 提供 snapshot、latest_running_id 和统一事件入口。
- `job:progress` / `job:done` / `job:failed` 使用完整快照加额外字段。

### A3-4 命令迁移

- launch、scan、install、插件操作、批量更新、共享 home 体检迁移到统一 Job sink。
- 旧事件继续发送，避免前端已有监听失效。
- 扫描取消同时写入旧全局标记和当前 scan token。

### A3-5 兼容矩阵回归

- 每个 DSH 版本使用独立 `DSH_HOME`，目录位于 `%TEMP%`。
- 检查 plugin add/remove/add、web 启动、state、无 cookie 401、带 cookie GET 405。
- 测试前后对真实数据根 `config.json` 做 SHA256 比对。
- 2026-11-11 结果：11 个版本全部通过。

### A3-6 文档、打包与验收

- 补齐本规划和验收清单。
- 更新 CHANGELOG、RELEASE_NOTES 和兼容矩阵。
- 执行本地打包，记录 exe SHA256。
- 完成用户验收后再合并和 tag。

### A3-7 原生 UIA 与更新链路自动化

- 新增 `scripts/acceptance-uia.ps1`：验证真实主窗口、版本号、插件面板、扫描取消、DSH 版本启动/关闭、日志和残留进程。
- 新增 `scripts/acceptance-update.ps1`：用本地 mock API 验证 SHA256、替换、`.old` 备份、旧进程退出和自动重启。
- 新增 `scripts/compat-matrix.ps1`：11 版本隔离兼容矩阵，默认 dry-run，`-Execute` 才执行。
- 三个脚本统一把报告写入 `.tmp/`，不提交构建产物或私有路径。
## 四、实施顺序

1. 先冻结 alpha.3 未提交基线，保留 diff 和未跟踪 adapter 文件。
2. 跑命令契约检查、E2E、Rust 测试、clippy、fmt 和前端构建。
3. 提交代码收口。
4. 补齐规划和验收清单，更新兼容矩阵与变更日志。
5. 本地打包，复制 exe 到固定位置并记录 SHA256。
6. 用户验收启动、插件、扫描、Job 和更新链路。
7. 验收通过后合并 main、推送并打 tag。

## 六、风险与回滚

| 风险 | 处理 |
| :--- | :--- |
| Job 事件字段变更导致前端不兼容 | 保留旧事件，新增字段只做增量 |
| adapter 能力门控误伤旧版本 | 未知版本和 v0.1 默认关闭 allow-version，用矩阵回归 |
| exe 替换失败 | 保留 `.old` 备份并回滚，不删除唯一可用副本 |
| 自动重启被单实例锁吞掉 | 延迟约 3 秒启动，避开旧进程退出窗口 |
| 兼容测试污染真实配置 | 独立 `%TEMP%` home，路径守卫，真实配置哈希比对 |
| 验收前误发布 | 本地验收通过后才合并 main 和打 tag |

## 七、已知边界

- 兼容矩阵验证的是安装、启动和协议冒烟，不是所有插件功能和 UI 行为的完整验收。
- 不覆盖跨版本实例聚合，留到 v0.4.0 主线。
- 不改变现有插件命令语义，也不承诺所有第三方插件在全部 DSH 版本可用。
- 兼容性自动脚本的长期入仓和 CI 化可在 alpha.3 验收后继续。
