# 自动更新测试方案

> 目标：覆盖 检查更新 -> 下载 -> SHA256 校验 -> 替换脚本 -> 重启 全链路，不依赖真实 GitHub Release。

## 1. 分层测试

### 1.1 纯函数单测
- is_newer：major/minor/patch、预发布后缀、非法版本、空字符串。
- GitHub JSON 解析：tag_name、html_url、exe asset、digest。
- 无 tag、无 exe asset、无 digest、HTTP 错误、非法 JSON。

### 1.2 本地 HTTP 集成测试
不访问 GitHub，使用 Rust 测试内嵌 TcpListener 充当 mock server。

场景：
1. releases/latest 返回新版本 + exe asset + sha256 -> check 返回 has_update=true。
2. 返回当前版本 -> has_update=false。
3. 返回 500 / 超时 / 非法 JSON -> error 非空，不崩溃。
4. download.exe 返回固定字节 -> download_and_verify 成功。
5. 返回错误 SHA256 -> 下载文件被删除并报错。
6. 无 SHA256 -> 允许下载，但记录风险。

实现建议：
- 给 updater::check 增加可注入 API base URL（环境变量 DSH_MULTIVER_UPDATE_API_BASE，默认 GitHub API）。
- 测试用 127.0.0.1:<port>，不引入外部依赖。

### 1.3 staged 替换测试
- pending 缺 sha / sha 错误 / 目标 exe 缺失 / .old 备份保留。
- 新增：验证替换脚本包含 wait -> copy -> restart 三段，不实际执行。

### 1.4 前端 E2E
- mock check_update 返回 has_update=true -> 显示更新横幅。
- 点击立即更新 -> 调用 perform_update，参数含 download_url/sha256。
- perform_update 失败 -> 显示可关闭错误提示，不误报成功。
- 当前版本/预发布版本不提示更新。

### 1.5 真实 Release 冒烟（手动）
1. 复制当前 exe 到临时目录 update-smoke/dsh-multiver.exe。
2. 启动本地静态 HTTP 服务，提供 mock releases/latest 和 download.exe。
3. 设置 DSH_MULTIVER_UPDATE_API_BASE=http://127.0.0.1:<port>。
4. 启动临时 exe，确认横幅出现。
5. 点击立即更新，确认下载、SHA 校验、批处理生成、重启到 mock 新 exe。
6. 验证旧 exe 备份 .old、临时文件清理、失败时旧 exe 不被破坏。

### 1.6 自动更新链路脚本

仓库提供 `scripts/acceptance-update.ps1`，把 1.5 的步骤自动化：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/acceptance-update.ps1 -StopExisting
```

脚本会：

- 在 `.tmp\acceptance-update-*` 下复制一份待更新 exe。
- 启动 `scripts/mock-update-server.mjs`，提供 mock `releases/latest` 和下载资源。
- 设置 `DSH_MULTIVER_UPDATE_API_BASE`，执行 `update --json`。
- 验证 SHA256、exe 替换、`.old` 备份、旧进程退出、延迟重启。
- 新进程启动后读取替换后的 `version --json`。
- 输出文本报告到 `.tmp\acceptance-update\`。

GUI「立即更新」按钮到真实替换命令的调用由 Playwright E2E 覆盖；真实替换和重启由该脚本覆盖。

## 2. 安全边界
- 没有 SHA256 时不自动替换，只提示；或明确警告后允许。
- 下载失败、SHA 不符、批处理失败都必须保留旧 exe。
- 自动更新只允许替换当前 exe，不接受任意目标路径。
- mock server 只用于测试，生产默认固定 GitHub API。

## 3. 验收
- cargo test --lib updater 覆盖纯函数与本地 HTTP 场景。
- E2E 覆盖更新横幅、成功/失败提示。
- 手动真实 Release 冒烟在临时目录完成，不动工作副本。
- 测试不访问真实 GitHub，不依赖开发机总是最新版本。
