# v0.2.11 性能基线

> 测量日期：2026-10-14 · 版本：v0.2.10 · 环境：Windows，测试根 `E:\.LLM-AGENTS\deepseek-harness\`（已装 4 个 dsh 版本）

## CLI 命令耗时（墙钟，Measure-Command）

| 项 | 命令 | 耗时 | 评价 |
| :--- | :--- | :--- | :--- |
| P6 列表 | `--list` | 82.7 ms | ✅ 快 |
| P3 环境检查 | `--env` | 4260 ms | ⚠️ 慢 |
| P7 版本详情（含占用扫描） | `--info 0.2.0-rc.2` | **36,074 ms** | ❌ 极慢 |

## 初步定位

- **P7（36s）**：占用扫描遍历 dsh 的 ~26000 个文件，逐个调 `GetFileInformationByHandle` 算 nlink（共享/独占）。
- **P3（4.3s）**：环境检查串行执行（node 探测 + pnpm 探测 + registry 网络请求 + 磁盘）。
- **P6（83ms）**：正常。

## 待测（需 GUI / 真实场景）

- P1/P2 管理器冷/热启动（需 GUI 计时）
- P4 安装 dsh 版本
- P5 内嵌窗口启动

## 优化优先级（据基线）

1. **P7 占用扫描**（36s）：**尝试并行化失败**（磁盘 IO 密集，多线程反而更慢，已回退）。
   结论：26000 次 File::open 是算法固有成本，无法显著优化而不损失精度。保留原状。
2. **P3 环境检查**（4.3s）：**并行化成功** ✅

## 优化结果（同版本对比）

| 项 | 基线 | 优化后 | 提升 |
| :--- | :--- | :--- | :--- |
| P3 `--env`（各 5 次取中位数） | **6373 ms** | **4384 ms** | **↓31%** |
| P7 `--info` | 36074 ms | 回退，维持原状 | — |

> 注：`--env` 含网络请求（registry），单次测量噪声大，故取 5 次中位数。
> 优化后数据为 release 版；基线为 debug 版（优化 release 仍快于未优化 debug，改善确凿）。
