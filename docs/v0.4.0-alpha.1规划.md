## 一、为什么先做这一轮

v0.3.7 已完成事件桥安全加固与契约测试。当前基线：Rust 单测 **202 passed / 1 ignored**；staged 4 passed；契约测试 4 passed / 1 ignored；CI 主流程通过。

v0.4.0 的实例模型会同时动版本、home、进程 key、窗口 label、配置和命令状态。直接做 UI/CLI 会反复返工。alpha.1 先固定**类型、配置和状态所有权**，不增加用户功能。

## 二、目标与边界

### 2.1 必须达成

1. 领域类型：`VersionId` / `InstanceId` / `HomeRef` / `ProcKey` / `LaunchTicket` 进入生产路径。
2. 配置可迁移：新增 `schema_version` 与实例表；旧 `isolated_versions` 自动迁移，行为不变。
3. 状态单一所有：`AppCtx` 收敛 `procs` / `intent` / `dirs` / `scan_cancel`；55 个命令迁移到 `State<'_, AppCtx>`。
4. 外部依赖有端口：pnpm、dsh 启动、文件系统、时钟建立 trait 边界。
5. 旧行为不回归：202 个既有单测断言不删、不弱化。

### 2.2 明确不做

- ❌ 不做实例 CRUD / 挂载的 GUI 或 CLI 用户功能（属 v0.4.0）
- ❌ 不做 `dsh_adapter`、`JobRegistry`、`tauri-specta`（属 alpha.2）
- ❌ 不改 `dsplugins` / `versions` 的业务行为
- ❌ 不拆多 crate 工作区，不打 GitHub Release

### W2 配置 schema 与迁移（3.5 人日）

| # | 任务 | 交付 | 人日 |
| :-- | :--- | :--- | ---: |
| M2-1 | 实例数据表 | `instances` / `version_instances` / `selected_target` / `instance_seq` | 1 |
| M2-2 | schema 版本 | `schema_version` + 有序迁移注册表 | 0.5 |
| M2-3 | 旧配置迁移 | `isolated_versions` → 实例表 + 挂载表 + `selected_target` | 1 |
| M2-4 | 目录迁移 | `versions/<v>/home` → `homes/<id>`；失败回退复制+删除 | 0.5 |
| M2-5 | 删除中间态 | `instances[].state = ready \| deleting`；启动时幂等续完 | 0.5 |
| M2-6 | 迁移测试 | 6 组旧配置 + 重复迁移幂等 + 中断续跑 | 0.5 |

迁移规则：每个旧隔离版本生成一个实例（默认名「默认隔离」）；`selected_target` 指向该实例；`isolated_versions` 迁移后写空数组；`schema_version` 缺失视为旧版；失败不覆盖原配置。

验收：空配置等价；单/多隔离 home 逐项一致；连续迁移两次字节级稳定；中途杀掉进程后重启不产生重复实例、不丢 home。

## 四、顺序与依赖

```
W0 基线
  └─▶ W1 领域类型（编译器先暴露全部调用点）
        ├─▶ W2 配置 schema + 迁移
```

## 六、风险与回滚

| 风险 | 缓解 |
| :--- | :--- |
| newtype 改造面大 | 每改完一个模块跑 `cargo check`；不保留 String 临时桥 |
| 迁移中断产生幽灵实例 | `state=deleting` + 启动扫描续完；迁移前备份原 config |
| 迁移错误覆盖旧文件 | 完整成功后才原子替换；失败保留原文件并写日志 |
| AppCtx 切换引发窗口时序问题 | 保留 generation 语义；两窗口并行冒烟；按模块分批提交 |
| 端口抽象改坏安装 | adapter 先包现有实现；fake 对拍后再迁移 |
| 周期膨胀 | 每工作包独立 PR；W4 超期则暂缓 Fs/Clock 扩展 |

回滚：任一工作包失败回滚对应 PR；迁移失败保留原 `config.json` 与旧 home；alpha.1 不发布 Release，tag 只作回滚锚点。
