## 二、A1：CLI 第 5 批

| 命令 | 用途 | 复用 |
| :--- | :--- | :--- |
| `--shortcut <版本>` | 无头创建桌面快捷方式 | `launcher::create_desktop_shortcut` |
| `--copy-shared <版本>` | 复制共享数据到隔离 home | `versions::copy_shared_to_isolated` |
| `--clear-isolated <版本>` | 清空隔离 home | `versions::clear_isolated` |

**约束（沿用第 2~4 批）**：
- 均支持 `--dry-run` / `--json`
- 无破坏性者（`--shortcut`）可不要 `--dry-run`，但为一致性保留
- 退出码：成功 0 / 失败 1
- 更新 `--help` + `docs/使用手册.md` + CHANGELOG

**实现要点**：
- 三个操作当前都在 `commands.rs`（依赖 AppHandle）→ 需抽出**不依赖 AppHandle 的纯函数**，CLI 与 GUI 共用
- `--shortcut`：Windows 专有（`.lnk`）；Unix 上应友好报错"当前平台不支持"

## 三、A2：i18n 后端检查项

**现状**：`envcheck.rs` 的 `CheckItem` 里 `name` / `detail` / `install_hint` 都是**硬编码中文**，
界面支持 4 语言但检查项名不跟随。

**方案**（最小改动）：
- `CheckItem` 增加 `name_key: String`（如 `"env.node.name"`），保留 `name` 作中文回退
- `detail` 保持原样（含动态版本号，不适合做 key）
- 前端：有 `name_key` 时优先 `t(name_key)`，否则用 `name`
- 词条表补 4 语言的检查项名

**不改**：`detail` 里的中文（如"满足 22.19+"）——动态内容，i18n 收益低、改动大，本次不做。

---

## 四、B1：WebView2 残留优化

**现状**：`maintenance.rs` 的 `cleanup_orphan_webviews` 在**启动时**清理"版本已不存在的 webview 目录"。
关窗/退出时**不清理**当前版本的 webview（保留登录态，这是对的）。

**待优化点**（先复现定位，再决定）：
- 内嵌窗口关闭后，`webview/<版本>` 是否残留锁文件/子进程？
- 管理器被强杀时，webview 目录是否残留？
- 现有 `procreg`（Unix）兜底到下次启动；Windows 用 Job Object

**原则**：**不能删掉正常关闭后的 webview**（那会丢登录态）。只清理"确定无用"的残留。

## 五、B2：数据备份/导出

**目标**：换机迁移。导出**配置 + 版本清单**（小体积），不导出依赖（大）。

**内容**：
- `config.json`（去掉机器相关字段？如 root_dir 可保留）
- 已安装版本清单（版本号 / 是否默认 / 是否隔离 / 安装日期）
- 可选：共享 home 的**会话/凭据**（体积小但敏感——默认**不含**，让用户选）

**形式**：
- GUI：路径设置区加「导出配置」按钮 → 保存为 `.json`（或 `.zip`）
- CLI：`--export [<文件>]`（可选，本批做）

**不做**：导入（导入涉及覆盖风险，单独排期）、依赖打包。
