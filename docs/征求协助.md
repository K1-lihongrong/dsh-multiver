# 征求协助：非 Windows 平台验证

> 本项目在 **Windows** 上开发与日常使用，**Linux** 已完成开发并通过 WSL 验证；
> **其他系统尚未验证**。这里列出**需要社区帮忙实测**的事项。欢迎提 [Issue](https://github.com/K1-lihongrong/dsh-multiver/issues)
> 反馈结果（成功或失败都欢迎）。

---

## 背景

dsh-multiver 的代码已跨平台化（`cfg` 分支隔离 Windows / Unix 逻辑），
在 **WSL2 + Debian 13** 上完成了编译、单元测试、GUI 启动、CLI、进程清理的验证。

但 WSL 与**真实 Linux 桌面**仍有差异（窗口系统、桌面环境、依赖版本等），
且 **macOS 完全没有验证过**。因此需要真机协助。

---

## 一、Linux 真机验证（优先）

### 已通过 WSL 验证的部分 ✅

- 编译（`cargo check` 零警告）、单元测试通过
- CLI：`--help` / `--list` / `--set-default` / `--uninstall` 正常
- 转发脚本：`~/.local/bin/dsh` 生成 / 删除正确
- 进程管理：进程组 + `PDEATHSIG`（管理器退出/被强杀时 dsh 进程树被清理）
- 打包：AppImage + deb 可构建（CI 产出）

### 待真机验证的部分 ❓

| # | 验证项 | 说明 |
| :-- | :--- | :--- |
| 1 | **内嵌窗口能否正常连接** | **重点**。WSLg 下内嵌窗口显示"重新连接中"（见 [GAP-008](开发缺口.md)），**真桌面是否复现未知** |
| 2 | AppImage 在干净系统能否运行 | 需 `libfuse2`（FUSE）；无则可能需 `--appimage-extract` |
| 3 | deb 安装/卸载 | `sudo dpkg -i` / `apt remove` |
| 4 | 桌面环境差异 | GNOME / KDE / XFCE 下的窗口、托盘、字体 |
| 5 | 桌面快捷方式 | `.desktop` 文件生成、双击启动（无桌面环境时会给出提示，属预期） |
| 6 | 终端短命令 | 敲 `dsh` 是否命中默认版本 |
| 7 | Wayland vs X11 | 两种会话下的行为 |

### 如何反馈

~~~bash
# 1. 下载 AppImage（或 deb）
chmod +x dsh-multiver_*_amd64.AppImage
./dsh-multiver_*_amd64.AppImage

# 2. 若内嵌窗口异常，请附上日志：
#    <数据根>/logs/ 下的 app.log / frontend.log / session-*.log
~~~

提 Issue 时请注明：**发行版 + 版本、桌面环境、X11/Wayland、是否复现问题 1**。

## 二、macOS 支持（有意愿者请举手）

代码目前**未适配 macOS**，但架构上不排斥（Tauri 本身支持 macOS）。适配大致需要：

| 项 | 现状 | 需要做 |
| :--- | :--- | :--- |
| 进程管理 | Unix 分支（进程组 + PDEATHSIG）| PDEATHSIG 是 Linux 特有，macOS 需换方案 |
| 终端短命令 | Windows `dsh.cmd` / Linux `~/.local/bin/dsh` | macOS 路径与 shell 约定 |
| 桌面快捷方式 | `.lnk` / `.desktop` | macOS `.app` 别名或 Finder 别名 |
| 构建发布 | Windows exe / Linux AppImage·deb | macOS `.dmg` / `.app`（需 Apple 开发者签名可选）|

**如果你有 macOS 环境并愿意帮忙验证/适配，欢迎在 Issue 里说明。**
