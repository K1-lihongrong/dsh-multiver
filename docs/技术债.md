## 一、说明

- **技术债** ≠ **功能缺口**。前者是"代码质量/结构/工程实践"的欠账；后者是"功能没做"（见开发缺口）。
- 每条标注：**类型 / 证据 / 状态 / 归属版本 / 风险**。
- 状态：`待修` / `已修（版本）` / `暂缓` / `不修（原因）`。

## 四、P7 全部思路的验证结论（汇总）

> 详见 [开发缺口 · P7 优化备选思路](开发缺口.md)。此处只列结论：

| 思路 | 结论 |
| :--- | :--- |
| A 放弃精度 | ❌ 与核心价值冲突 |
| B 卷级接口 | ❌ 需管理员权限 |
| C 内存 inode 去重 | ❌ 版本内 inode 不重复 |
| D 遍历 store | ❌ store 比版本还大 |
| E 整包判定 | ❌ 包内 nlink 不一致 |
| F 读 pnpm 账本 | ❌ pnpm 无文件级账本 |
| G 合并 open | ❌ 实测无收益 |
| **根本原因** | **NTFS 硬链接 1024 上限 + 同内容可独立** → 无捷径 |
| 缓存（未列入 A~G） | ✅ 已在 v0.2.13 实现（版本级缓存 `sizecache.rs`） |

## 五、维护约定

- 发现新债 → 追加 D 条目（编号递增）
- 修复后 → 状态改 `已修（版本）`
- 决定不做 → 移入"未做的修复"，注明原因
- 每项附**可复现证据**（命令输出 / 行数 / 实测）
- **每版发布后复检**：行数/单测数等实测证据会随开发变化，需重新测量并更新。
