### 零.1 隐藏系统标题栏黑条

**现象**：管理器主窗口顶部有系统原生标题栏（深色，含应用图标、标题、「DSH 版本管理器」文字与窗口三键），其下又是应用自己的蓝色顶栏（鲸鱼 logo + 版本号 + 根目录）。两层叠加，视觉冗余。

**根因**：`src-tauri/tauri.conf.json` 的窗口配置未设 `decorations: false`，默认保留系统标题栏。

**方案**：
- `tauri.conf.json` 窗口配置加 `"decorations": false`，Windows 上配 `"titleBarStyle": "overlay"`
- `App.vue` 的 `.topbar` 加 `data-tauri-drag-region`，恢复拖动能力
- 在 `.topbar` 右侧补最小化 / 最大化 / 关闭三个按钮（调用 `@tauri-apps/api/window` 的 `minimize/toggleMaximize/close`）
- 双击顶栏空白区最大化 / 还原

**风险（必须实测）**：
- **任务栏图标与分组**：项目有 `set_process_aumid` / `register_aumid_icons` / `set_window_app_user_model_id` 一整套 AUMID 逻辑（CUCKOO.md §10 记录为已知痛点）。无边框窗口在 Windows 上的任务栏行为与有边框不同，改完必须验证图标不丢、不与管理器窗口错误合并。
- 窗口圆角与阴影：Windows 11 下无边框窗口需自行处理或接受直角。

**不做**：不改内嵌 dsh 窗口（那个窗口本来就无系统标题栏，由注入的 topbar.js 提供工具条）。

### 零.2 安装进度条平滑化

**现象**：安装 dsh 版本时，进度条长时间停在同一百分比，然后一次跳几个百分点，观感"卡顿"。

**根因**（已定位）：
- 后端 `versions/install.rs:361` 节流阈值为 `fraction` 变化 ≥ 0.01 才推事件
- pnpm 在「写入文件」阶段（前端权重 55，占 35%→90% 区间）输出不均匀，大量硬链接写入时可能几百毫秒无输出，一旦输出就跳多个包
- 前端 `.prog-fill` 无 CSS 过渡，宽度瞬变

**方案（两侧都改）**：
- **数据侧**：后端节流阈值 `0.01` → `0.003`（更密的事件）
- **视觉侧**：`.install-progress .prog-fill` 加 `transition: width 0.3s ease-out`，让每次变化平滑滑过去
- **可选**：前端加一个 200ms 定时器，在两次事件之间按上次 step 的线性插值缓慢爬升，直到下一事件到来。若实现复杂度超出预期，可只做前两项。

**约束**：
- 不得改变阶段权重表（`STAGE_START` / `STAGE_WEIGHT`），那套权重按实际耗时分配，调了会让整体节奏失真
- 不得让进度回退（后端已有 `clamp_step` 防回退，前端保持）

### 零.3 推荐页分类标签多语言

**现象**：切到韩语（或英、日、繁中）后，插件推荐页的分类标签（版本管理 / 远程访问 / 终端界面 / 工具增强 / 费用统计 / 主题皮肤 / 内容聚合 / 可视化）仍显示中文。卡片描述也有同样问题（部分插件缺对应语言的 `descriptionI18n`）。

**根因**（已确认）：
- `DsPluginCatalog.vue:80-82` 的 `catalogCategories` 把 `label` 直接设为 `p.category` 原值，不走 `t()`
- `docs/plugins.json` 的 `category` 字段是中文硬编码，且**没有多语言机制**
- 各插件的 `descriptionI18n` 只有 zh-TW / en-US / ja-JP 三种，**缺 ko-KR**

**方案**：完全复用 `descriptionI18n` 的既有模式（`catalog.rs:40-47` + `DsPluginCatalog.vue:199-201`），不发明新机制。

1. **数据层** `docs/plugins.json`：
   - 顶层新增 `categoryI18n` 映射表，key 为中文原值：
     ```json
     "categoryI18n": {
       "版本管理": { "zh-TW": "版本管理", "en-US": "Version management", "ja-JP": "バージョン管理", "ko-KR": "버전 관리" },
       ...
     }
     ```
   - 各插件的 `descriptionI18n` 补 `"ko-KR"` 一项（9 个插件）
   - `version` 保持 2（新增可选字段不算破坏性变更）
   - `updatedAt` 更新为发布当天，确保 `load_local` 取新内置副本

2. **Rust 层** `catalog.rs`：
   - `RawCatalog` 加 `#[serde(rename = "categoryI18n", default)] category_i18n: Option<HashMap<String, HashMap<String, String>>>`
   - `Catalog`（前端拿到的结构）同样加该字段，透传给前端
   - **不**加到 `CatalogPlugin`（分类是全局映射，不是每插件各一份）
   - 单测：`category_i18n_is_parsed`、`category_i18n_optional_for_legacy`（照 `description_i18n_is_parsed` 写法）

3. **前端** `DsPluginCatalog.vue`：
   - `catalogCategories` 里 `label: c` 改为 `label: catalog.value?.categoryI18n?.[c]?.[currentLang.value] || c`
   - **`key` 保持 `c` 原值不变**，`catalogItems` 的过滤逻辑零改动
   - E2E：新增「切韩语后分类标签显示韩语」用例

**兜底**：
- 旧缓存（磁盘上的 plugins.json 副本）无 `categoryI18n` → `serde(default)` 为 `None` → 前端 `|| c` 回退中文原文，行为与现在一致
- `descriptionI18n` 缺某语言 → `descOf` 已回退 `|| p.description`，不需改

**已验证的设计约束**：分类的 `key` 参与筛选（`catalogItems` 用 `category` 原值相等匹配），改 key 会破坏筛选。故 key 必须保持原值。

## 一、要解决的问题

`docs/插件兼容矩阵.md` 当前结论是「最低已验证版本 `0.1.5-rc.3`」，但这句**只说明 rc.3 能用**，不能说明 rc.3 以下都不能用。同时，当前 `verifiedDshVersions` 最后登记的是 `0.2.1-rc.3`，之后发布的版本一个都没验证过。

后果：用户在未验证版本上遇到问题时，**无法判断是插件 bug 还是 dsh 版本差异**。插件页面会显示「未验证版本」黄条，但用户拿不到「到底支不支持」的答案。

## 三、判定口径（必须先定，否则结论无法比较）

每个版本按矩阵现有 5 列判定：装插件 / 启动 / `state` / 401 鉴权 / 405 方法。

**「支持」** = 5 列全 ✅。
**「不支持」** = 插件装上但某项端点行为不符合预期（这是插件要修的问题）。
**「无法判定」** = dsh 自身装不上或起不来，与插件无关。**必须写明具体错误**，不能笼统写「失败」。

> 关键区分：`fs-ext` 编译失败、Cordis HMR 报错属于 dsh 自身问题 → 「无法判定」而非「不支持」。这个口径写进文档，避免后人误读为插件不兼容。

## 四、执行方法

沿用 `docs/插件兼容矩阵.md` 第 57 行的复现方法，不另造流程：

1. 用 multiver 在测试根 `E:\.LLM-AGENTS\deepseek-harness\` 装目标版本
2. 为该版本准备独立 `DSH_HOME`（`%TEMP%\compat-<版本>`）
3. `dsh plugin --profile web add <插件 tgz>`
4. `dsh web --port <独立端口> --no-open` 启动
5. 验 `state`（带 token）/ 401（不带 token）/ 405（GET）
6. 记录结果，清理临时版本与 home

**测试纪律**（沿用现有约定）：测前快照真实 `config.json` 的 SHA256，测后核对未变；临时 `DSH_HOME` 全部放 `%TEMP%`，测完移入回收站；临时版本用 `uninstall` 清理，不留 `broken_versions` 标记。

## 六、风险与边界

| 风险 | 应对 |
| :--- | :--- |
| 旧版本 `fs-ext` 编译失败，无法验证 | 标记「无法判定」，记录错误原文，不强行绕过 |
| 早期版本依赖已下架私有包 | 安装失败即记「无法判定」，不重试换源 |
| 测试版本多，磁盘占用 | 每测完一个立即 `uninstall`，不留存量 |
| 误动真实数据根 | 全程用独立 `DSH_HOME`，测前快照 `config.json` |

**不在本轮范围**：改插件兼容性代码、放宽安装层约束（当前已是零约束）、补 macOS 验证。
