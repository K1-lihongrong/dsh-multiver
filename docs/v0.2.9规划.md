# v0.2.9 开发规划 —— 运行时适配

> 编写日期：2026-10-13 · 基线：v0.2.8
> 定位：**运行时适配**（让环境不齐的用户也能用起来）。**无破坏性变更**。
> 分支：`feat/v0.2.9`
> 关联：[开发缺口](开发缺口.md)、[使用手册](使用手册.md)

---

## 一、要解决的问题

不同用户的电脑环境差异大。当前工具只做"检查 + 给下载链接"，用户要自己找、自己装，门槛高。典型缺失：

| 缺失 | 影响 | 现状 |
| :--- | :--- | :--- |
| **WebView2** | 管理器**根本起不来**（Tauri 本体依赖） | 只在"已知限制"里提了一句 |
| **Node.js**（没装 / 版本不符） | 装不了、跑不了 dsh | 环境检查提示，用户自理 |
| **pnpm**（没装 / 过低） | 装不了 dsh 依赖 | 环境检查提示，用户自理 |
| ~~VC++ 运行时~~ | —— | **经查不需要**（见第四节） |

**目标**：**默认零操作或极简操作**，把用户从"环境门槛"里解放出来。

---

## 二、总体策略（已确认的决策）

| 组件 | 策略 |
| :--- | :--- |
| **WebView2** | **主 exe 早期检测**（Tauri 初始化前）+ **Win32 原生弹窗**引导：[自动下载并安装] / [打开下载页] |
| **VC++ 运行时** | **不做**（Rust 静态链接 CRT，UCRT 系统自带） |
| **Node 缺失** | **自动下载便携 Node** 到数据根（零操作）+ **引导装系统 Node**（可选，完善终端体验） |
| **Node 版本不符** | 引导升级；便携 Node 兜底 |
| **用户后装系统 Node** | **自动降级用系统的**；便携 Node **保留**（兜底）+ 界面可手动清理 |
| **pnpm** | **优先系统 pnpm** → 兜底**按需下载独立版** → 引导 |
| **下载源** | **优先官方源**，失败提示换源（复用现有"换源重试"逻辑） |
| **存放位置** | 数据根内（`<数据根>/tools/node/`、`<数据根>/tools/pnpm/`）—— 自包含 |
| **平台范围** | **仅 Windows**（Linux 保持引导） |
| **exe 体积** | **不变**（~9MB）—— 一切**按需下载**，**不内置** |

**关键原则**：
- **不内置进 exe**（保住"约 7MB 单 exe"的轻量卖点）
- **不偷偷下**（启动时检测 → 提示 → 用户确认后下载）
- **不污染系统**（运行时放数据根内；不改系统 PATH / 不装全局）

## 三、分批实施（同一版本内）

### 批 1：自动下载（先让"能跑起来"）

**目标**：全新环境（无 Node / pnpm）也能零操作装起 dsh。

#### 1.1 便携 Node 下载
- 从 Node 官方 distributions 下载 `node-v22.19.0-win-x64.zip`（~30MB）
- 解压到 `<数据根>/tools/node/`
- 备用源：淘宝镜像 `npmmirror.com/mirrors/node`（官方失败时提示）

#### 1.2 pnpm 独立版下载
- 优先用**系统 pnpm**（P2/P3 情况）
- 系统没有 → 下载 pnpm standalone 到 `<数据根>/tools/pnpm/`
- 备用源：同换源逻辑

#### 1.3 运行时解析顺序
每次装/跑 dsh 时判断：
1. **系统 Node 符合**（`^22.19.0` 或 `>=24`）→ 用系统的
2. **系统 Node 不符** → 用便携 Node（若有）+ 引导升级
3. **都没有** → 下载便携 Node
- 便携 Node 目录**加进 dsh 子进程 PATH**（让 Agent 也能用 `node`）

#### 1.4 触发时机
- 管理器启动 → **检测**环境 → 缺运行时 → **提示**"将自动准备运行时（便携 Node ~30MB / pnpm ~10MB）"
- 用户**确认**后下载（**带进度**）
- 完成后可用
- **不提前下、不偷偷下、不临时卡壳**

#### 1.5 运行时管理入口
- 界面提供"**清理内置运行时**"按钮（用户想省磁盘时手动清）

#### 1.6 便携 Node 保留策略
- 用户后来装了系统 Node → **自动降级用系统的**，便携 Node **保留**（兜底）
- **不自动删**（系统 Node 可能又被卸载/降级）

### 批 2：引导（完善体验）

#### 2.1 WebView2 早期检测（与批 1 同源实现）
- **时机**：`main.rs` 最早，**Tauri 初始化之前**（纯 Rust / Win32）
- **方式**：读注册表 `HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` 的 `pv` 值（微软官方推荐）
- **缺失** → `MessageBoxW` 弹**原生框**（不依赖 WebView2）：
  - **[自动下载并安装]** → 下 Evergreen Bootstrapper（~2MB）→ `ShellExecute` 拉起 → 装完提示重启
  - **[打开下载页]** → `ShellExecute` 打开微软下载页
  - 直接关窗 → 退出

#### 2.2 WebView2 下载策略
- 优先 **Bootstrapper**（~2MB，联网装）
- 下载失败（如离线）→ 引导用户下 **Standalone**（~130MB，离线包）
- 检测到包管理器（winget）→ 附赠命令 `winget install Microsoft.EdgeWebView2Runtime`

## 四、为什么不做 VC++ 运行时（调查结论）

**调查**（2026-10-13，分析 release exe 的 DLL 导入表）：
- exe 依赖：`api-ms-win-crt-*.dll`（**UCRT，Win10+ 系统自带**）+ 一堆系统 DLL
- **没有** `vcruntime140.dll` / `msvcp140.dll`（VC++ Redistributable 的标志）

**结论**：
- Rust（Windows MSVC 目标）**默认静态链接 CRT** → **不依赖 VC++ 运行时**
- UCRT 自 Win10 起是系统组件，**不用装**
- 项目 README "已知限制"从没提 VC++，侧面印证

**所以**：**取消 VC++ 处理**。批 2 聚焦 WebView2。

---

## 五、不做的事（明确）

- **不内置**便携 Node / pnpm 到 exe（体积不变）
- **不做 VC++** 检测/安装（不需要）
- **不做 Linux** 的自动下载（Linux 保持引导）
- **不自动全局安装** Node/pnpm 到系统（不污染）
- **不静默安装** WebView2（用户点几下确认）

## 六、验收标准

### 批 1（自动下载）
- [ ] 全新环境（无 Node/pnpm）→ 管理器启动 → 提示"将准备运行时" → 确认后**自动下载**便携 Node + pnpm
- [ ] 下载完成后 → 能正常**装 dsh 版本** → 能**运行**（内嵌窗口）
- [ ] **exe 体积不变**（~9MB）
- [ ] 系统有 Node 时 → **优先用系统的**，不下载

### 批 2（WebView2 引导）
- [ ] 缺 WebView2 → 主 exe **早期检测** → 弹 **Win32 原生框**（两选项）
- [ ] [自动下载并安装] → 下 bootstrapper + 拉起安装
- [ ] [打开下载页] → 打开微软页
- [ ] 有 WebView2 → 正常进入

### 通用
- [ ] `cargo test` 全绿
- [ ] 前端渲染验证（Playwright + vite preview）
- [ ] release 打包正常

## 七、技术要点

- **WebView2 检测**：`windows-sys` 加 `Win32_System_Registry` feature；`MessageBoxW` / `ShellExecuteW` 用 `Win32_UI_WindowsAndMessaging` / `Win32_UI_Shell`
- **下载**：复用 `reqwest`（已有 `blocking`）；下载到临时文件 → 校验 → 解压（zip 用 `zip` crate）
- **解压**：Node zip 解压（`zip` crate）
- **PATH 注入**：spawn dsh 时把便携 Node 目录加进子进程环境
- **换源**：复用现有"换源重试"的源列表（官方/淘宝/腾讯/华为）
