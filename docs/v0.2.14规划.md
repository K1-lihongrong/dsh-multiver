# v0.2.14 开发规划 —— 启动加载页

> 编写日期：2026-10-16 · 基线：v0.2.13
> 定位：**体验优化**（无破坏性变更）。为"启动无提示"补一个加载页。
> 分支：`feat/v0.2.14`
> 关联：[技术债](技术债.md)（U8）

---

## 一、问题

**快捷方式启动时，有几秒完全无提示。**

快捷方式带 `--launch-version <版本>` 启动，流程是：

1. 启动 exe → **隐藏主窗口**（`lib.rs`）
2. 后台起 dsh web（**数秒**，最坏 90s 超时）
3. dsh 地址就绪 → 建内嵌窗口

**第 2 步期间屏幕上无任何窗口** → 用户"双击后几秒没反应"，以为故障。

**"运行"按钮启动**同类问题（主界面在，但只是按钮变文字，反馈弱）。

---

## 二、方案（已确认）

**统一"启动加载页"**：主窗口显示一个加载界面，直到 dsh 窗口就绪。

### 形态
- **复用主窗口**（不新增窗口、不写原生 Win32 splash）。
- 内容：**版本号 + "正在启动…" + 转圈动画**（可选小 logo）。
- 出现时间：约 1s（实测窗口就绪 ~892ms，WebView2 固有）。

### 两入口共用
| 入口 | 现在的表现 | 改后 |
| :--- | :--- | :--- |
| **快捷方式** | 主窗口隐藏 → 全程空白 | 主窗口**显示加载页** → dsh 窗口就绪后关闭 |
| **运行按钮** | 主界面 + 按钮变"启动中…" | 主界面**切成加载页** → dsh 窗口就绪后恢复/关闭 |

两者后台都走 `launch_window`，前端统一成一个"启动中"状态。

### 图片可行性
- **可放图片**（小 logo），建议 **SVG 或 128px 内联**，代价可忽略（几 KB、本地无网络请求）。
- **不要放大图**（如 500KB 背景），会拖慢首屏。

### 失败处理
- 启动失败 → 加载页显示错误信息（版本 + 原因 + "查看日志"指引），而非直接关掉。
- 现状：失败时把主窗口 `show()` 出来（`lib.rs`），用户看到的是管理器主界面，不知道刚启动失败了。

---

## 三、改动面（预估）

| 层 | 文件 | 改动 |
| :--- | :--- | :--- |
| 后端 | `lib.rs` | 精简启动模式：不再"隐藏主窗口"，改为"通知前端进入加载态" |
| 后端 | `commands.rs` | `launch_window` 进度事件（准备/启动 dsh/等待地址） |
| 前端 | `App.vue` | 新"启动中"全屏态（版本号 + 转圈 + 可选 logo + 失败显示） |
| 前端 | `InstalledList.vue` | 运行按钮触发同一加载态 |
| 文案 | `i18n/*.js` | 4 语言：正在启动 / 启动失败 / 查看日志 |

---

## 四、验收标准

- [ ] 快捷方式启动：~1s 后出加载页（不再全程空白）
- [ ] 加载页显示版本号 + "正在启动…" + 转圈
- [ ] "运行"按钮启动同样进入加载页
- [ ] 启动失败：加载页显示错误 + 日志指引（不直接消失）
- [ ] 4 语言正常
- [ ] `cargo test` 全绿 / clippy / fmt / 渲染验证

## 五、不做

- ❌ 大图背景
