## 二、A. CLI 子命令重构

**详见** [CLI重构计划-v0.3.0](CLI重构计划-v0.3.0.md)。要点：

- `--list` → `list`，`--install X` → `install X`，`--set-default X` → `set-default X` …
- 修饰符（`--json` / `--dry-run`）**语法不变**
- 可选嵌套子命令（`version list` / `default set X`）
- **破坏所有现有脚本** → 需**迁移指南**（随 Release Notes）

**决策点**（做时拍板）：是否嵌套分组、是否保留 `--help/--version`、是否双轨过渡。

## 三、B. dsh 双向桥

### 3.1 设想（用户描述）

**双向桥**：
1. **dsh 界面内** → 调 **dsh-multiver CLI** → 管理版本（列/切/装）
2. **dsh-multiver 界面内** → 为 **dsh 安装/调试插件**

### 3.2 关键问题（✅ 已调研，2026-10-20）

**调研结论：dsh 插件机制基本成熟，双向桥可行。**

证据（来自 `@deepseek-ai/dsh` 0.2.1-alpha.3 依赖）：
- `dsh plugin add/remove/list`：**插件 = npm 包**，装在 profile 目录（转发 pnpm）。
- `dsh-plugin-manager`：插件管理器。
- `dsh-client-ui-cordis`：**客户端 UI 插件**（可在界面加 UI）。
- `cordis-plugin-loader` / `dsh-cordis-client-runner`：插件加载/运行。
- 官方自身大量 `dsh-tool-*` / `dsh-experimental-*` 就是插件（验证机制可用）。

**两个方向**：
1. **dsh 界面 → 调 dsh-multiver**：写 dsh 客户端 UI 插件，加"版本管理"入口，调 `dsh-multiver.exe`。
2. **dsh-multiver → 管理 dsh 插件**：界面加"插件管理"，调 `dsh plugin add/remove/list`。

**难点**：
- `dsh-client-ui-cordis` 的 **API 无公开文档**（需读源码或问社区）。
- cordis 框架有学习成本。
- alpha 阶段 API 可能变。

**建议顺序**：
- **先做方向 2**（简单、风险低：multiver 侧调 CLI，不改 dsh 内部）。
- **方向 1 后置**（需深挖 cordis）。

> ⚠️ **前置依赖（用户确认）**：插件要调 CLI，**CLI 必须先稳定**（块 A 定稿）。所以 v0.3.0 **先做 A，B 后置到 A 完成后**。

### 3.3 依赖

- 桥的"dsh 侧"是一个 **dsh 插件**（通过 `dsh plugin add` 装）
- 桥的"multiver 侧"是 dsh-multiver **界面 + CLI**

**前置**：CLI（块 A）**先定稿**，桥按新语法开发。

### 3.4 待办

- [ ] 调研 dsh 插件能力（UI 扩展 / 调外部命令 / 发布机制）
- [ ] 出详细方案（接口设计、数据流、权限）
- [ ] 实现 dsh 侧插件
- [ ] 实现 multiver 侧的插件管理界面

> **注**：用户计划**用 DeepSeek Harness 进行具体开发**——本文件出规划，实现交给 dsh。

## 四、C. macOS 适配

**前置**：需要 **macOS 真机**验证。若没有，**延后**。

需做（见 [征求协助](征求协助.md)）：
- 进程管理：`/proc` 读进程身份 → macOS 换 `proc_pidinfo`
- 终端短命令：macOS 路径与 shell 约定
- 桌面快捷方式：macOS `.app` 别名或 Finder 别名
- 构建发布：macOS `.dmg` / `.app`（签名可选）
