## 二、A. CLI 子命令重构

**详见** [CLI重构计划-v0.3.0](CLI重构计划-v0.3.0.md)。要点：

- `--list` → `list`，`--install X` → `install X`，`--set-default X` → `set-default X` …
- 修饰符（`--json` / `--dry-run`）**语法不变**
- 可选嵌套子命令（`version list` / `default set X`）
- **破坏所有现有脚本** → 需**迁移指南**（随 Release Notes）

**决策点**（做时拍板）：是否嵌套分组、是否保留 `--help/--version`、是否双轨过渡。

---

## 三、B. dsh 双向桥

### 3.1 设想（用户描述）

**双向桥**：
1. **dsh 界面内** → 调 **dsh-multiver CLI** → 管理版本（列/切/装）
2. **dsh-multiver 界面内** → 为 **dsh 安装/调试插件**

### 3.2 关键问题（待调研）

⚠️ **dsh 插件机制是否成熟？**（用户确认"需先调研"）

需确认：
- dsh 插件能否**在界面里加 UI**（如"版本管理"入口）？
- dsh 插件能否**调用外部 CLI**（`dsh-multiver.exe`）？
- dsh 插件的**发布/安装机制**是否就绪？

**调研对象**：dsh 官方插件文档、示例、生态。

### 3.3 依赖

- 桥的"dsh 侧"是一个 **dsh 插件**（通过 `dsh plugin add` 装）
- 桥的"multiver 侧"是 dsh-multiver **界面 + CLI**

**前置**：CLI（块 A）**先定稿**，桥按新语法开发。

### 3.4 待办

- [ ] 调研 dsh 插件能力（UI 扩展 / 调外部命令 / 发布机制）
- [ ] 出详细方案（接口设计、数据流、权限）
- [ ] 实现 dsh 侧插件
- [ ] 实现 multiver 侧的插件管理界面

> **注**：用户计划**用 DeepSeek Harness 进行具体开发**——本文件出规划，实现交给 dsh。

## 四、C. macOS 适配

**前置**：需要 **macOS 真机**验证。若没有，**延后**。

需做（见 [征求协助](征求协助.md)）：
- 进程管理：`/proc` 读进程身份 → macOS 换 `proc_pidinfo`
- 终端短命令：macOS 路径与 shell 约定
- 桌面快捷方式：macOS `.app` 别名或 Finder 别名
- 构建发布：macOS `.dmg` / `.app`（签名可选）

---

## 五、不做的事（明确）

- **不做** CLI 双轨兼容（R3，建议直接切）
- **不改**内部参数风格（`--launch-version` / `--debug-progress`）
- **不强行**做 macOS（无真机则延后）
