## 1. L-18 浏览器打开（三场景）

设计依据：[交互设计约定 §2.1](交互设计约定.md#21-浏览器打开open_in_browser)。核心约束：**任何平台不得牺牲控制台窗口**；关掉控制台窗口即停止服务。

### L-18a 有终端模拟器 + 有浏览器

**步骤**

1. 确认 `x-terminal-emulator` / `xterm` / `gnome-terminal` / `konsole` / `xfce4-terminal` / `alacritty` / `kitty` 至少存在一个。
2. 提供一个假浏览器（`BROWSER=/tmp/fake-browser.sh`，记录收到的参数）或安装真实浏览器。
3. GUI 点「浏览器打开」→ 处理「共享 home 提示」→「继续运行」。

**预期**

- 弹出一个**终端窗口**，其中运行 dsh，能看到 dsh 实时输出（含完整 URL 与 token）。
- 浏览器被打开，URL 与终端输出一致。
- 关闭该终端窗口 → dsh 进程停止。
- 管理器退出 → 该 dsh 继续存活（设计如此，非残留）。

**判定**：以上四条全部满足为通过。

**证据**：终端窗口截图（URL/token 打码）、假浏览器记录文件、`pgrep -af dsh` 关窗前/后输出、`app.log` 相关行。

### L-18b 有终端模拟器 + 无浏览器

**步骤**

1. 确认系统无任何浏览器（`xdg-open` 返回 3）。
2. 同 L-18a 触发「浏览器打开」。

**预期**

- 终端窗口仍出现，dsh 正常运行。
- **URL 与 token 在终端窗口中可见、可复制**。
- 浏览器交接失败的原因在终端可见（不是被吞进日志文件）。
- 关闭终端窗口 → dsh 停止。

**判定**：用户能在终端拿到可访问 URL 为通过。

**证据**：终端窗口截图（token 打码）、`curl` 带该 token 访问返回 HTTP 200 的记录。

### L-18c 无终端模拟器

**步骤**

1. 临时把全部候选终端模拟器移出 PATH（或用最小 PATH 启动）。
2. 触发「浏览器打开」。

**预期**

- **明确报错**，提示缺少终端模拟器，并给出安装引导。
- **不回退到静默后台运行**（不得出现「已启动」toast 但无任何可见窗口的情况）。
- 管理器不崩溃。

**判定**：有明确错误提示且无静默后台为通过；出现静默后台为不通过。

**证据**：报错弹窗或 toast 截图、`app.log` 对应行、`pgrep -af dsh` 确认无后台残留。

## 2. R-12 镜像完全未发布子包（`ERR_PNPM_NO_VERSIONS`）

背景：报告 §6.4 记录该场景曾被归为 `unknown`，仅弹 toast、无换源入口；已在 `cc1b295` 修复。

**步骤**

1. 启动 stub registry（如 `127.0.0.1:4873`），**完全不发布**某子包（如 `@aws-sdk/types`）。
2. 配置指向该源，GUI 安装 `0.2.1-rc.2`。

**预期**

- pnpm 返回 `ERR_PNPM_NO_VERSIONS`。
- 弹出与 L-31 相同的**换源重试弹窗**（含源下拉 +「换源重试」），分类为 `incomplete-version`。
- 选官方源后安装成功。
- 不再只弹 toast。

**判定**：出现换源弹窗且换源可成功为通过。

**证据**：弹窗截图、`原始错误` 展开截图、安装成功截图、`app.log` 分类相关行。

## 3. D18 配置损坏恢复

**步骤**

1. 手工把 `<数据根>/config.json` 写成非法 JSON（如截断、加乱码）。
2. 启动管理器。

**预期**

- 管理器**不崩溃**，正常启动并给出默认/可用配置。
- 原文件被保留为 `.broken-<时间戳>`（在数据根或同目录）。
- 日志有明确警告（`app.log` 记录损坏与备份路径）。

**判定**：三项全部满足为通过。

**证据**：`.broken-*` 文件 `ls -l` 输出、`app.log` 警告行、启动后界面截图。

## 4. D19 数据根不可写

**步骤**

1. 把数据根设为只读（`chmod -R a-w` 或挂只读）。
2. 启动管理器。

**预期**

- 界面出现**不可关闭的横幅**（不能点 × 消失）。
- 横幅提供「去设置」入口，可跳转到路径设置。
- 不崩溃、不静默失败。

**判定**：横幅不可关闭 + 有设置入口为通过。

**证据**：横幅截图、尝试关闭无效的记录、跳转设置截图、`app.log` 相关行。

## 5. D20 Node 版本过低文案

**步骤**

1. 把 PATH 指向 Node 22.16.0（满足 `import.meta.main` 缺失场景）。
2. 运行 `env --json` 并查看 GUI 环境检查。

**预期**

- CLI `env --json`：Node 项 `critical=true`、exit 1，`detail` 写明「版本过低」并给出下限（22.19+ 或 24.2+）。
- **不出现**「未找到 node」这类错误文案。
- GUI 环境检查显示「版本过低」及安装引导。

**判定**：文案为「版本过低」且带下限说明为通过。

**证据**：`env --json` 输出、GUI 环境检查截图。
