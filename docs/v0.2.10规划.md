# v0.2.10 开发规划 —— 自动更新 C2

> 编写日期：2026-10-13 · 基线：v0.2.9（预计）
> 定位：**自动更新（下载 + 替换自身）**。**无破坏性变更**（对用户），但**技术风险高**，单独一版充分测试。
> 分支：`feat/v0.2.10`
> 关联：[开发缺口](开发缺口.md)（Backlog 的"自动更新 C2"）

---

## 一、背景

**C1（更新提醒）已在 v0.2.6 完成**：启动后查 GitHub Releases 最新版本，有新版显示横幅 + 下载链接。

**C2（本版）目标**：从"提醒 + 手动下载"升级到"**一键更新**"——管理器**自动下载新 exe → 替换自身 → 重启**。

**为什么单独一版**：涉及"**替换运行中的自身 exe**"，风险高（失败可能导致程序损坏），值得单独充分测试。

---

## 二、要解决的问题

便携版用户升级现状：
1. 看到更新提醒 → 点"下载更新"→ 跳到 GitHub Release 页
2. 手动下载 `dsh-multiver.exe`（新的）
3. 手动关闭旧程序、替换文件

**痛点**：步骤多（跳浏览器、找文件、关程序、替换），普通用户易出错。

---

## 三、方案（待细化）

### 3.1 技术选型

| 方案 | 说明 |
| :--- | :--- |
| **A. Tauri updater 插件**（`tauri-plugin-updater`） | 官方方案，但**面向"安装器/打包"场景**，便携单 exe 的自替换需额外处理 |
| **B. 自实现** | 下载新 exe → 用批处理/辅助进程替换自身 → 重启 |

**倾向**：**先调研 A 是否支持便携 exe**；否则自实现（B）。

### 3.2 替换自身 exe 的难点（Windows）

**核心问题**：Windows 上**运行中的 exe 不能被覆盖**。

**常见解法**：
- **辅助批处理**：写一个 .bat，等主程序退出 → 复制新 exe 覆盖 → 重启 → 自删
- **重命名旧 exe + 新 exe 就位**：旧 exe 改名（如 `.old`），新 exe 写入原位置，重启后旧 exe 删除

### 3.3 安全校验

- 下载后**校验 SHA256**（Release 需提供校验文件或摘要）
- **签名**（可选，但推荐；若做签名需改 CI）

### 3.4 CI 改造

- Release 需提供**校验信息**（如 `latest.json` 含版本 + 下载 URL + SHA256）
- 可能需**签名**（Tauri updater 要求签名）

### 3.5 失败回滚

- 下载/替换失败 → **保留旧 exe**，不损坏
- 提供"手动下载"回退路径（即现有 C1 的链接）

## 五、不做的事（明确）

- **不做后台静默更新**（用户知情、确认后更新）
- **不做增量更新**（全量替换 exe，简单可靠）
- **不做 Linux/macOS 自动更新**（本版仅 Windows；Linux 走包管理器）
