# v0.4.0-alpha.2 规划：适配层、任务收敛与共享 home 体检

> 创建日期：2026-11-09 · 基线：**0.4.0-alpha.1**（tag `0.4.0-alpha.1`，提交 `8b0ae0e`）
> 状态：**规划完成，待启动**
> 上层路线：[后续版本路线图.md](后续版本路线图.md) §五
> 分支：`feat/v0.4.0-alpha.2` · 周期定位：**适配层与任务模型收敛，不发布 GitHub Release**

---

## 一、为什么做这一轮

alpha.1 已完成配置迁移、AppCtx、插件批量更新/回滚、精确版本豁免和检查更新修复。但插件域仍有四个结构性问题，直接做 v0.4.0 实例 UI 会反复返工：

1. `dsplugins` 仍是一个大模块，安装、profile、catalog、exempt 混在一起。
2. 安装、扫描、插件、更新、启动仍是五套进度/取消模型。
3. 插件安装与 GUI/CLI 的完成账本还没有统一入口。
4. 共享 home 的 `profiles/node_modules` 是跨版本模块链接农场，旧版本残留会让新版 DSH 误判整个 profile 不兼容。

alpha.2 的目标是**把适配层和任务模型稳定下来**，同时补一个只读的共享 home 体检，专门解释旧版本残留为什么会阻止新插件安装。

---

## 二、目标与边界

### 2.1 本轮目标

1. dsh 版本适配收敛到 `dsh_adapter` trait，支持 v0.1 / v0.3 两代行为。
2. `dsplugins` 按职责拆成可独立测试的子模块，外部命令签名不变。
3. 安装、扫描、插件、更新、启动统一进 `JobRegistry`，前端只监听 `job:*`。
4. 插件安装接入统一 Job，GUI 与 CLI 共用完成账本。
5. 前端 `invoke` 迁移到 `src/api/`，生成并校验 TS bindings，错误按 `code` 分类。
6. 新增共享 home 健康检查：只读扫描旧 junction、悬空链接、跨版本残留和不兼容来源。
7. 清掉 alpha.1 留下的纯 `app` 命令迁移技术债。

### 2.2 明确不做

- 不做 v0.4.0 的实例 UI、`IsolatedMenu` 重写、全局实例面板。
- 不自动删除共享 home 的 junction。
- 不把 `dsh-plugin` 拉进内核。
- 不引入 Pinia。
- 不做视觉重设计，只做必要的诊断入口与状态展示。
- 不发布 GitHub Release，只打轻量 tag `0.4.0-alpha.2`。

## 三、工作包

### A2-1 dsh 适配层（M4-1）

- 产出：`dsh_adapter` trait、`v0_1.rs`、`v0_3.rs`、`detect.rs`。
- 统一 CLI 路径、profile 目录、兼容性检查、版本能力开关。
- 未知版本走最小安全默认。
- 验收：至少两个已安装版本走真实 CLI 冒烟；adapter 单测覆盖识别/未知版本。

### A2-2 dsplugins 拆分（M4-2）

拆为：

```text
dsplugins/
  install.rs      # add/remove/事务/回滚
  profile.rs      # profile 读取、版本、lockfile/状态
  catalog.rs      # 推荐列表、inspect、registry 探测
  exempt.rs       # allow/revoke/version-exemptions
  diagnostics.rs  # 共享 home / 旧 junction / 兼容性归因
  mod.rs          # 公共 API 与 re-export
```

硬约束：命令签名、JSON 字段、前端行为不变；只移动代码和加测试。
### A2-3 插件安装接入统一 Job（M4-3）

- 安装/卸载/更新命令统一创建 `JobId`。
- 进度、完成、失败都走 `job:*` 事件。
- 完成账本由 `InstallService::finish()` 统一处理，GUI 与 CLI 不再各写一套。
- 不安全取消的路径保持不可取消，不伪造取消能力。

### A2-4 JobRegistry（M5-1）

```text
JobId + CancellationToken + EventSink
```

- 每个 Job 有稳定 id、类型、目标（版本/profile/实例）、开始时间。
- `EventSink` 统一发 `job:progress` / `job:done` / `job:failed`。
- 扫描、安装、插件、更新、启动各接入一次。
- Job 历史只保留最近 N 条，避免长会话内存增长。

### A2-5 五套进度/取消收敛（M5-2）

| 当前模型 | 收敛后 |
| :--- | :--- |
| `install-progress` | `job:progress` |
| 扫描 size 事件 | `job:progress` |
| `ds-plugin-progress` | `job:progress` |
| `plugin-update-progress` | `job:progress` |
| `launch-progress` | `job:progress` |

前端只保留一个 Job 订阅层，组件按 job type 过滤。取消只对扫描等安全路径开放；安装/插件操作继续明确提示不可取消。

### A2-6 InstallService 完成账本（M5-3）

- `finish()` 统一做：清理临时目录、写 broken 标记、更新状态、发完成事件。
- GUI 与 CLI 共用同一套 finish 规则。
- 增加「成功但需要重启/需要豁免」的结果状态，避免把部分成功伪装成全成功。

### A2-7 set_root 两侧校验统一（M5-4）

- GUI 与 CLI 对根目录的检查项、错误码、提示文案一致。
- 覆盖：不存在、不可写、路径含空格、盘符根、网络盘、旧配置迁移。
- 新增 GUI/CLI 对照测试。

### A2-8 TS bindings + api 层 + ErrorKind（M7-1 到 M7-5）

- `tauri-specta` 生成 `bindings.ts` 并入库。
- 前端 64 处裸 `invoke` 迁移到 `src/api/`。
- `check-commands.mjs` 升级为生成物与源码一致。
- 错误统一为 `{ code, message, detail }`，前端按 code 分支，不再全靠字符串匹配。

### A2-9 壳与列表拆分（Opt-1 到 Opt-4）

- `App.vue` 拆壳、列表、浮层。
- `InstalledList.vue` 拆 `InstalledRow`。
- `envcheck.rs` 表驱动化。
- i18n 全量校验。
- 目标是把后续实例 UI 的改动面降下来，不做视觉重设计。
### A2-10 共享 home 健康检查（新增）

这是本轮唯一新增的用户可见诊断功能。

#### 检测内容

1. `home/profiles/node_modules` 中的 junction / symlink。
2. 链接目标是否指向 `versions/<version>/...`。
3. 链接目标是否存在，识别悬空链接。
4. 同一包是否同时来自多个 DSH 版本。
5. 包是否只在共享父目录，不在当前 profile 的 `package.json` / lockfile。
6. 来源包版本与当前 DSH 运行时的 peer 要求是否明显不匹配。

#### 报告形态

```json
{
  "home": "...",
  "current_version": "0.2.2-rc.1",
  "summary": { "scanned": 0, "stale": 0, "dangling": 0, "duplicate": 0 },
  "issues": [
    {
      "kind": "stale_junction",
      "package": "@deepseek-ai/dsh-agent-presets",
      "source_version": "0.0.1-rc.5",
      "target": "...",
      "detail": "..."
    }
  ]
}
```

#### 交互

- 插件面板或维护面板增加共享 home 体检入口。
- 报告只读展示，提供打开来源目录、复制诊断报告、建议给当前版本建隔离 home、建议允许精确版本（有风险）。
- 不提供自动删除；清理必须由用户明确执行并先备份。

#### 验收

- 能识别当前机器上来自 `0.0.1-rc.5` 的两个旧官方包。
- 悬空 junction、重复版本、无问题三种 fixture 都有测试。
- 扫描 1,000 条链接不超过 2 秒。
- 报告不修改任何文件。

### A2-11 W3 剩余命令迁移（技术债）

alpha.1 已把状态敏感命令迁到 `AppCtx`；剩余纯 `app` 命令不持有可变状态。

本轮目标：

- 统一通过 `AppCtx` 或只读 `ctx.config_and_dirs()` 获取目录/配置。
- 命令签名逐步改为 `State<AppCtx>`。
- 不改变任何命令行为与 JSON 字段。

## 六、风险与回滚

| 风险 | 处理 |
| :--- | :--- |
| Job 事件收敛导致旧组件收不到进度 | 保留一个版本的兼容转发层，alpha.3 再删 |
| dsplugins 拆分改变命令语义 | 先移动 + 回归测试，行为改动单独提交 |
| 共享 home 体检误判 | 只报告、不删除；所有结论附来源路径和证据 |
| GUI/CLI 账本统一引入回归 | 以现有 CLI 结果为准，新增对照测试 |
| tauri-specta 生成物与手写类型漂移 | CI 比对生成物，禁止手改 bindings |
| 壳拆分影响实例 UI 前置工作 | 只拆不改视觉，E2E 全量回归 |

回滚策略：每个工作包独立提交；Job 事件层、dsplugins 拆分、体检模块均可单独 revert；tag 只作回滚锚点。
