## 三、原生自动化验收

仓库提供三层可重复执行的验收脚本：

```powershell
# 原生窗口 UI Automation：真实 WebView + 真实 Rust 后端
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/acceptance-uia.ps1 -StopExisting

# 一键更新链路：mock API -> 下载 -> SHA256 -> 替换 -> 自动重启
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/acceptance-update.ps1 -StopExisting

# 11 版本兼容矩阵，默认 dry-run
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/compat-matrix.ps1 -Execute
```

报告与截图默认输出到：

```text
.tmp\acceptance-uia\
.tmp\acceptance-update\
.tmp\compat-matrix\
```

`acceptance-uia.ps1` 自动检查：

- 主窗口启动、版本号、已安装版本列表
- 插件面板打开和已安装列表
- 扫描开始、取消、按钮恢复
- 指定 DSH 版本启动窗口、等待 frontend.log 出现 topbar 注入就绪、窗口关闭、子进程清理
- 测试期间的日志 panic / unhandled error
- 关闭后是否残留 dsh-multiver 进程
- 关键界面截图

补充说明：

- 默认启动 `0.2.2-rc.1`，可用 `-LaunchVersion` 指定其他已知可启动版本。
- `-StopExisting` 会关闭已有 dsh-multiver 实例，仅用于验收机。
- 如需覆盖共享 home 版本，可再跑一次并指定 `-LaunchVersion 0.2.2-alpha.3`。
- 原生 UIA 覆盖真实后端；Playwright E2E 继续负责纯前端交互和 mock 场景。

`acceptance-update.ps1` 自动检查：

- mock release API 和下载资源
- SHA256 校验
- 当前 exe 替换为新 exe
- `.old` 备份及其 SHA256
- 旧进程退出、新进程自动重启
- 重启后执行 `version --json`
- 更新成功后临时文件和工作进程清理

GUI「立即更新」按钮到 `perform_update` 的调用由 Playwright E2E 覆盖；真实替换与重启由 `acceptance-update.ps1` 覆盖。
