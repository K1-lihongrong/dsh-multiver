# 交互设计约定

> 记录**用户可见的交互设计意图**及其理由。这些设计不是随意的，改动前必须理解为什么。
> 与 `docs/技术债.md`（代码层面欠账）分工：本文管「**应该长什么样**」，技术债管「**实现有什么欠账**」。

---

## 1. 为什么要这个文档

v0.3.0 期间发生过一次设计意图丢失：

- **原设计**：GUI「浏览器打开」新开一个控制台窗口，由 dsh 自己打开浏览器。
  理由：用户需要看到 dsh 实时输出（含 token）、需要「关窗即停」的直觉操作，与用户自己开终端敲 `dsh web` 一致。
- **被改掉**：Linux 验收发现「无浏览器时静默失败」，修复时（`0299b89`）顺手改成「管理器捕获 URL 后自行打开」，
  控制台窗口消失、dsh 输出被吞进日志文件。**Windows 用户可见行为被改变，无人察觉。**
- **根因**：设计意图只存在于代码注释里。注释被改写后，意图就消失了。验收清单写的是
  「无浏览器时应弹窗展示完整 URL」——把**实现方案**当成验收标准，开发者按字面执行，不会回头问原设计。

**结论：用户可见的交互设计必须有独立于代码的记录，并标注「不可随意改变」。**

## 2. 约定条目

### 2.1 浏览器打开（`open_in_browser`）

**设计**：新开一个控制台窗口运行 dsh，由 dsh 自己打开系统默认浏览器。

**理由**：
- 用户能看到 dsh 的实时输出（含完整 URL 与 token），可自行复制
- 「关掉控制台窗口即停止服务」，与用户自己开终端敲 `dsh web` 的心智模型一致
- 显式的窗口让用户明确知道「这个东西在跑」

**约束**：

1. 任何平台的无浏览器 / 打开失败处理，**不得牺牲控制台窗口**。
2. **管理器退出时不得杀死浏览器模式的 dsh。** 它由用户显式启动的控制台窗口承载，
   「关掉控制台窗口才停止」是设计的一部分。管理器退出后它继续存活是**正确行为**，不是残留。
   - 对比：**内嵌窗口**的 dsh 由管理器管理（Windows 挂 Job Object、Unix 走进程组 + `procreg`），
     管理器退出/崩溃时应被清理，否则是缺陷（GAP-010）。
   - 代码依据：`spawn_web_console` 调用 `spawn_web_inner(..., attach_job: false)`，注释明确
     「**不挂 Job**：浏览器模式进程允许在管理器退出后继续运行」。
3. **端口 3080 被占用时必须让用户选择，不得自动换端口。** 弹对话框提供「用随机端口」与「取消」两条路径。
   - 理由：自动换端口会让用户记不住地址；固定端口是「浏览器打开」的可预期性来源之一。
   - 代码依据：`launch.rs:332-353`（`port_in_use` 检测 + 原生对话框）。

**变更流程**：如需改变（如统一为后台进程），先在此节说明理由并获得确认，再改代码。

**平台实现**：Windows 用 `CREATE_NEW_CONSOLE`；Linux 查找系统终端模拟器
（`x-terminal-emulator` / `xterm` / `gnome-terminal` / `konsole` / `xfce4-terminal` / `alacritty` / `kitty`）
承载同一启动脚本，找不到时**明确报错**，不得静默退化为后台进程。CLI `run` 仍走 detached 实现。

**相关代码**：`src-tauri/src/launcher/process.rs::spawn_web_console`（Windows → `spawn_web_console_detached`；
Linux → 终端模拟器）、`src-tauri/src/commands/launch.rs::open_in_browser`。

### 2.2 内嵌窗口运行（`launch_window`）

**设计**：dsh 跑在 Tauri 内嵌窗口里，隐藏控制台，URL 由管理器解析。

**理由**：这是本工具的核心体验——不需要用户面对终端；多版本可各开窗口；关闭窗口即结束整棵进程树。

**约束**：内嵌窗口必须保持「隐藏控制台」；不得改为可见终端窗口。

### 2.3 终端短命令（`dsh` 转发脚本）

**设计**：设默认版本时在 `%APPDATA%\npm\`（Windows）或 `~/.local/bin`（Unix）生成 `dsh` 转发脚本，写死版本号 / 根目录 / DSH_HOME。

**理由**：让用户在终端敲 `dsh` 就能进默认版本，无需记住完整路径；转发脚本与 GUI 用同一套 DSH_HOME 解析逻辑，保证行为一致。

**约束**：转发脚本必须带 `dsh-multiver-generated` 标记（避免误删用户自己的 dsh）；必须带 Node 能力守卫（`import.meta.main` 探测）。

### 2.4 失败换源（`ERR_PNPM_NO_MATCHING_VERSION`）

**设计**：安装因镜像源未同步而失败时，弹窗展示「选择源」下拉 + 「换源重试」按钮，不直接失败退出。

**理由**：镜像同步滞后是上游生态问题，用户无法通过重试解决；换源是唯一有效出路，但用户不知道该换哪个。

**约束**：弹窗文案不得与换源入口自相矛盾（如「无法安装」+「换源重试」并存）；换源后保留原版本号与安装方式。

### 2.5 配置损坏处理（管理器 `config.json`）

> ✅ **已实现**（v0.3.0，技术债 D18）。

**设计**：启动时检测管理器 `config.json` 是否损坏；损坏则**写警告日志** + **把原文件重命名为 `config.json.broken-<时间戳>`** 保留现场 + 回退到默认配置继续启动。

**理由**：
- 配置是辅助性的，损坏不应阻断启动
- 但用户的 `isolated_versions` 标记丢失会导致**隔离版本变回共享 home**，会话数据位置悄悄改变——这比「默认版本丢失」后果严重
- 保留原文件可人工恢复；日志可追溯

**约束**：
- 回退时**不得删除**原文件，必须重命名保留
- 日志必须包含损坏原因（JSON 解析错误的具体位置）
- 检测只在**启动时**做一次（新增 `Config::load_checked()`，供 `lib.rs` 与 `cli/mod.rs` 调用）；`Config::load()` 保持纯读取、无副作用

**变更流程**：如需改变（如改为弹窗提示），先在此节说明理由并获得确认。

**相关代码**：`src-tauri/src/config.rs::Config::load`（当前静默回退，无日志）。

### 2.6 数据根不可写

> ✅ **已实现**（v0.3.0，技术债 D19）。

**设计**：启动时检查数据根是否可写；不可写则在界面顶部显示**不可关闭的横幅**，内容含当前根目录路径 + 「去设置修改」入口。根目录改好后横幅自动消失。

**理由**：
- 数据根不可写时，后续所有操作都会失败，但失败点分散在安装、卸载、运行各处，用户看不出根因
- 横幅集中告知，比让用户在多个地方遇到「莫名其妙的失败」好
- 不可关闭：这是持续状态，不是一次性事件。用户关掉后仍会失败，反而更困惑
- 对比：更新检查失败的横幅是**可关闭**的，因为那是一次性事件

**约束**：
- 横幅必须**含当前根目录路径**，否则用户不知道改哪个
- 必须提供「去设置修改」入口，不能只提示
- 不阻断启动（用户可以看帮助、改设置）
- 根目录可写后横幅自动消失，无需重启

**变更流程**：如需改变（如改为启动弹窗阻断），先在此节说明理由并获得确认。

**相关代码**：`src-tauri/src/config.rs::Dirs::ensure`（8 处调用点，7 处用 `let _ =` 忽略错误）。

### 2.7 单实例（重复启动与版本快捷方式）

> ✅ **已实现**（v0.3.0 · M2m，技术债 D17）。

**设计**：管理器只允许一个实例。第二实例启动后立即退出，把意图转交给已运行实例：

- 无参数 → 已运行实例的主窗口 `unminimize + show + set_focus`；主窗口不存在（被 `--launch-version` 流程关闭过）则按 `tauri.conf.json` 重建。
- 带 `--launch-version V`（版本桌面快捷方式）→ 在已运行实例里打开该版本的内嵌窗口；该版本已有窗口时聚焦它，不重开。

**理由**：

- 两个实例共享同一 `config.json` 与 `versions/`，同时写会互相覆盖（D17 记录的三类风险）
- 「多开对比版本」是过度设计：同一个管理器内各版本各开一个内嵌窗口即可完成对比
- 版本快捷方式的核心语义是「打开这个版本的 dsh」，不是「再开一个管理器」——单实例下必须保留这个语义，否则管理器一开着所有快捷方式就失效

**约束**：

- 回调**必须**转发 `--launch-version`，不能只做「聚焦主窗口」
- 主窗口被关闭时必须能重建，否则双击图标无反应
- 重建前**必须清除启动态**（`LAUNCH_MODE`）。否则重建出的主窗口前端会读到旧的 `--launch-version` 值，进入「正在启动」且收不到后续事件，永久卡住
- 转发 `--launch-version` 失败时（如版本未安装）**回退到确保主窗口存在并聚焦**，同时把错误写入 `logs/app.log` 与 `logs/launch-error.log`；release 版无控制台，`eprintln` 不可作为唯一手段

**有意差异**：转发 `--launch-version` 时主窗口**保持打开**（不 close）。这是与「桌面快捷方式直接启动」的差别——后者以 `--launch-version` 作为进程首个参数启动，主窗口在 dsh 窗口建好后关闭；单实例转发发生在已运行进程中，主窗口已存在且用户可能正在用，不应关闭。
- **CLI 不能被单实例拦截**：`dsh-multiver list --json` 等命令必须在 `tauri::Builder` 之前分流并立即退出
- 前台锁导致 `set_focus` 失败时退化 `request_user_attention`，不得静默失败

**不同副本被拦截时的用户可见行为**：锁按应用标识 `io.github.K1-lihongrong.dsh-multiver` 全局生效，同一用户下两个不同目录的副本也不能同时运行。此时：

- **不转发** `--launch-version`（不同副本可能用不同数据根，转发会操作错数据）；
- 弹原生对话框，标题「已有管理器在运行」，正文列出**已运行副本**与**本次启动副本**的路径，并提示「请使用已运行的窗口，或先关闭它再启动本副本」；
- 聚焦已运行的实例；
- 写 `logs/app.log`（`[single-instance] 拦截不同副本启动：second=… current=…`）。

判定方式：比较第二实例的 `args[0]` 与 `std::env::current_exe()`，先 `canonicalize`（展开 8.3 短路径与符号链接），Windows 忽略大小写。

若将来必须按数据根区分，再改自实现锁（`<root>/.manager.lock` + named mutex）。

**变更流程**：如需恢复多开，先在此节说明理由并获得确认。

**相关代码**：`src-tauri/src/lib.rs`（plugin 注册与回调）、`src-tauri/src/window.rs::ensure_main_window`（主窗口恢复/重建）。

### 2.8 网络下载的镜像回退（GitHub 依赖）

> ✅ **已实现**（v0.3.2 + 插件 0.2.1，`src-tauri/src/net.rs` + `dsh-plugin/lib/download.js`）。

**设计**：所有依赖 GitHub 的下载，按固定顺序尝试多个源，任一成功即返回。分两类：

| 用途 | 源顺序 | 超时 |
| :--- | :--- | :--- |
| **exe 下载**（Release 资产：multiver 自身更新、插件部署、插件暂存更新） | 直连 `github.com` → `gh-proxy.com` | 每个源 15–20 秒 |
| **推荐列表**（`docs/plugins.json`，纯文本 JSON） | 直连 `github.com` → `gh-proxy.com` → `cdn.jsdelivr.net` | 直连 5 秒，其余 15 秒 |

推荐列表直连超时短，因为它是非关键路径——拉不到就用内置副本，不必让用户干等。

**理由**：

- **没有代理的用户占多数**。此前 multiver 的 `updater.rs` 依赖系统代理设置（R-04 读注册表），但那只解决装了代理软件的用户；插件侧的 `https.get` 根本不读系统代理。两者叠加的结果是：无代理 + 直连不通的用户，更新和部署完全不可用。
- **项目已有先例**。`runtime/bundled.rs` 下载 Node 与 pnpm 时已内置「官方 → npmmirror」回退（注释原文：「源顺序：官方 → 淘宝镜像。任一成功即返回」）。这次是把同一模式推广到所有 GitHub 依赖点，避免「有的地方有回退、有的地方没有」的割裂。
- **直连优先**。官方源可用时不引入第三方，减少对公共反代的依赖与攻击面。
- **内置镜像列表，不让用户配置**。普通用户不会去设 `HTTPS_PROXY`，也不该需要理解什么是反代。镜像失效时通过发版更新，而不是让用户自己改配置。

**约束**：

- **失败判定不能只看状态码**。公共反代最常见的问题是「返回 200 但内容是 HTML 错误页」。exe 下载要校验前几个字节（Windows PE 为 `MZ`），JSON 要能解析成功，否则视为该源失败并继续下一个。
- **插件侧下载白名单必须同步扩充**。`lib/pure.js` 的 `checkDownloadUrl` 目前只允许三个 GitHub 域名，新增镜像域名要一并加入，否则会被直接拒绝。扩白名单等同于扩攻击面，只收录实测可用的镜像。
- **记住上次成功的源**，同一进程内优先复用，失败才重新按序尝试，避免每次请求都付一遍超时成本。
- **镜像列表硬编码**，不做用户可配置项。排查问题时通过日志输出「本次实际使用的源」，用户能上报即可。

**镜像可用性实测**（2026-10-30，厦门，无代理环境）：

| 目标 | 结果 |
| :--- | :--- |
| `github.com` → `release-assets.githubusercontent.com`（真实 Release 资产） | ✅ 200，2.1 秒 |
| `raw.githubusercontent.com` | ❌ 超时（10 秒无响应） |
| `gh-proxy.com` 代理同一 Release 资产 | ✅ 200，1.6 秒 |
| `cdn.jsdelivr.net` | ✅ 200，0.55 秒 |
| `registry.npmmirror.com` | ✅ 200，0.1 秒 |
| `ghfast.top` | ❌ 403 |
| `ghproxy.net` | ❌ 403 / 5.3 秒 |

注意 `github.com` 通但 `raw.githubusercontent.com` 不通，这是国内网络的典型状态——不能笼统认为「GitHub 能通」或「GitHub 不通」。

**变更流程**：新增或替换镜像时，需同时更新本节表格、`lib/pure.js` 的下载白名单、以及代码里的镜像列表；三者不一致会导致「白名单拒绝了自己配置的镜像」。

**相关代码**：`src-tauri/src/net.rs`（统一回退实现）、`src-tauri/src/updater.rs`（multiver 自身更新）、`src-tauri/src/runtime/bundled.rs`（Node/pnpm 回退，尚未收编到 net.rs）、`dsh-plugin/lib/download.js`（插件侧下载）、`dsh-plugin/lib/pure.js::checkDownloadUrl`（域名白名单）。

### 2.9 推荐插件页（`DsPluginPanel` 的「推荐」标签）

> ✅ **已实现**（v0.3.2）。

**设计**：插件面板工具栏加入「已安装 | 推荐」分段切换。推荐页展示一份可安装的插件清单，点「安装」复用已安装标签的安装对话框。

**列表格式**（`docs/plugins.json`）：

纯静态 JSON，随仓库发布。顶层字段：

| 字段 | 必填 | 类型 | 说明 |
| :--- | :---: | :--- | :--- |
| `version` | ✅ | number | schema 版本。将来不兼容变更时递增；读到不认识的版本应拒绝解析并回退到内置副本 |
| `plugins` | ✅ | array | 条目数组 |

条目字段：

| 字段 | 必填 | 类型 | 说明 |
| :--- | :---: | :--- | :--- |
| `name` | ✅ | string | 包名，列表主标题。无 `spec` 时同时是安装用的 spec；有 `spec` 时仅用于展示与「是否已安装」判定 |
| `description` | ✅ | string | 一句话描述，建议 60 字以内 |
| `category` | ✅ | string | 分类名。**自由文本，靠人工克制**——新增插件时优先复用已有分类，避免最终变成「一插件一分类」而失去分组意义 |
| `repo` | ✅ | string | 仓库地址。UI 渲染「GitHub ↗」链接 |
| `spec` | 可选 | string | 安装地址，覆盖 `name`。用于包名不能直接装的情况（npm 上版本落后、包不在 npm 上）。必须是 `ds_install_plugin` 可接受的形式 |
| `minDshVersion` | 可选 | string | 最低 dsh 版本。**语义是「低于此版本装不上」**（对应 `engines.dsh`），UI 应禁用安装按钮并提示，而不是让用户点了再失败。缺失表示无特殊要求 |
| `tags` | 可选 | string[] | 标签。`same-author` = 与本软件同作者；`featured` = 推荐置顶。**两者都会在列表中排最前并显示 ⭐**，悬停提示分别是「同作者」和「推荐」 |
| `noNpm` | 可选 | boolean | 该包在 npm 上不存在。为 true 时 UI **不渲染**「npmjs ↗」链接，避免 404 |
| `hidden` | 可选 | boolean | 暂时下架。为 true 时条目不显示，但保留记录，便于恢复 |

**npmjs 链接的生成规则**：默认按 `https://www.npmjs.com/package/<name>` 拼。`name` 是 scoped 包（含 `/`）时直接拼也能跳转，npm 会做 URL 编码。标了 `noNpm: true` 的不生成。

**新增条目的流程**：编辑 `docs/plugins.json` → 本地跑一遍 JSON 校验 → 确认 `spec` 能被 `validate_package_spec` 通过 → 提交。**不需要发版**——文件是运行时拉取的，改完推送即生效（用户端受本地缓存与检查节流影响，可能滞后）。

**数据的三层结构**：

| 层 | 位置 | 角色 | 何时更新 |
| :--- | :--- | :--- | :--- |
| 1 | `docs/plugins.json`（编译期 `include_str!`） | 首次打开时的初始内容 | 随版本发布 |
| 2 | `<数据根>/cache/plugins.json` | 上次成功拉取的内容 | 每次检查发现远端不同时覆盖 |
| 3 | 远端 `main` 分支的 raw 文件 | 检查更新时的比对源 | 每次 push |

**打开推荐页的流程**：

1. `ds_plugin_catalog` 读本地——有磁盘缓存用缓存，无缓存用编译期内置。**不联网，立即返回**
2. `ds_plugin_catalog_check` 后台拉远端，与本地做 sha256 比对
3. 比对基准：有磁盘缓存用缓存，无缓存用内置副本
4. 内容不同 → 校验远端能解析 → 写入磁盘缓存 → 返回 `updated: true` → 前端重新读本地并渲染
5. 网络失败 → 保留当前内容，顶部显示「可能不是最新」+ 重试按钮

**检查节流**：30 分钟内重复进入推荐页不重新检查；用户点分类栏右侧的 ↻ 按钮可强制检查。

**为什么用 sha256 而不是版本号**：内容差异就是唯一需要关心的事实，不必依赖人工维护 `rev` 字段（忘记递增就失效）。JSON 只有几 KB，每次全量下载的成本可忽略。

**为什么保留编译期内置**：断网或镜像全挂时推荐页仍有内容可看，而不是空白页。代价是发版后内置副本与远端可能不一致——联网用户拿到的是远端最新，断网用户看到的是发版时的快照。

**列表呈现**：

- **单网格**，与已安装列表共用 `minmax(320px, 1fr)`，宽屏多列、窄屏单列。
- **卡片双行**：第一行是图标 + ⭐ + 包名 + 徽标 + 安装按钮；第二行是 GitHub / npmjs 链接 + 单行描述 + 「查看完整描述」。
- **不按分类分组**。分类由标签栏承担；分组会让每组末行填不满，产生多条参差边缘。
- **星标置顶**：带 `featured` 或 `same-author` 的条目排最前并显示 ⭐，与 `category` 无关。悬停提示分别是「推荐」和「同作者」。

**分类标签栏**：全部 / 各分类，按列表中出现顺序去重。分类多到溢出时右侧出现 `‹ ›` 滚动控件；右侧另有常驻的 ↻ 按钮用于手动检查更新。

**描述与浮窗**：

- 行内只显示一行描述，溢出时右侧渐隐（`mask-image` 淡出右端 25%）。短描述到不了该区域，自然完整显示。
- **悬停热区限定在描述文字与「查看完整描述」**，不扩展到整张卡片——否则鼠标划过包名或安装按钮也会弹出浮窗，挡住操作。
- 触发方式三种：悬停在描述区 400ms、点击「查看完整描述」、点击卡片。**点击卡片上半部分不触发**。
- 浮窗只放完整描述，**不放链接**（链接在行内，避免浮窗内点击）。实色背景（半透明会让背后的卡片透出来），进出场淡入 160ms / 淡出 120ms，带上浮 4px。
- 鼠标移出时按 `relatedTarget` 判断：移向浮窗则保留（可选中文字），移向其他元素立即关闭。

**外部链接**：GitHub 与 npmjs 走 `invoke("open_url")`，**不能用 `<a target="_blank">`**——Tauri WebView 里后者不触发系统浏览器。`open_url` 命令只接受 http/https 前缀。

**相关代码**：`src-tauri/src/catalog.rs`（三层数据与比对）、`src-tauri/src/commands/plugins.rs`（`ds_plugin_catalog` / `ds_plugin_catalog_check`）、`src/components/DsPluginCatalog.vue`（推荐页 UI；v0.3.3 起从 `DsPluginPanel.vue` 拆出）。

### 2.10 版本豁免（v0.4.0-alpha.1 恢复）

> ✅ **已恢复**。dsh 0.2.2-rc.1 起，`dsh plugin` 自己拦截 `allow-version` / `revoke-version` / `version-exemptions` 三个子命令，不再转发给 pnpm。

**交互**：

- 安装失败输出里出现 `Plugin pkg@ver is incompatible with dsh runtime` 时，对话框自动解析出精确版本豁免项。
- 展示「允许此精确版本」/「允许全部 N 个并重试」；点击后调用官方 CLI `dsh plugin --profile <p> allow-version <pkg@ver> --dsh-version <runtime> --accept-risk`，成功后自动重试安装。
- 同时展示可手动执行的完整命令，便于排障。
- profile 信息区展示已有精确版本豁免，可逐项撤销。

**约束**：

- 只调用官方 CLI，不直接写 `compatibility.json`。
- 旧版 dsh 不支持这些子命令时，错误原样透传，不做假成功。
- 不把「允许」做成静默自动放行：用户必须看到风险提示并主动点击。

**相关代码**：`src/components/DsPluginInstallDialog.vue`、`src/components/DsPluginMeta.vue`、`src/composables/useDsPluginErrors.js`、`src-tauri/src/commands/plugins.rs` 的 `ds_exemption_action`。缺口记录见 `开发缺口.md` B1-19。

### 2.11 按钮交互动效（v0.3.4，技术债 D22）

> ✅ **已实现**（v0.3.4，`src/styles/common.css` + `src/styles/dsplugins.css`）。

**设计**：全站所有可点击控件共用**一套**反馈语言，参数收进 4 个 CSS 令牌。此前主界面与插件面板各有一套，同一屏内并存。

| 维度 | 统一后 | 此前 |
| :--- | :--- | :--- |
| 悬停底色 | `--surface-3` 浅底 | 主界面 `--gray-hover` / 插件面板 `--surface-3` |
| 悬停描边 | 主色 `--accent-border` | 主界面深灰 `--border-strong` / 插件面板主色 |
| 按下反馈 | 底色加深 + `scale(.97)` | **全站均无** |
| 焦点环 | 全站 2px 主色 `:focus-visible` | 仅插件面板有；主界面走浏览器默认虚线框 |
| 主按钮悬停 | 变深 + 主色光晕 | 主界面变深 / 插件面板 `filter: brightness(1.08)` 变亮且瞬变 |
| 危险按钮悬停 | 实心红底白字 | 主界面令牌浅底 / 插件面板硬编码 `rgba(229,72,77,.08)` |

**理由**：

- **同一屏内不该有两种反馈语言**。用户在插件面板与主界面之间移动鼠标，按钮手感不应切换。这是 v0.3.3 只改过渡属性后仍存在的割裂——差异不止过渡，而是 6 个视觉维度。
- **点击需要落点感**。此前全站按钮都没有 `:active` 样式，按下与未按下完全一致，快速点击时用户不确定是否命中。
- **键盘用户此前被区别对待**。主界面按钮按 Tab 走浏览器默认虚线框，插件面板是主色焦点环。统一为主色焦点环后，键盘导航有了可辨识的当前位置。
- **参数集中管理**。4 个令牌（`--motion-fast` / `--motion-base` / `--ease-standard` / `--press-scale`）让后续调参只改一处，不再逐个控件搜索。

**约束**：

- **悬停不得改变文字颜色**。只换底色与描边。实测过 hover 时加深文字，在浅灰底上观感"发黑"，已放弃。
- **`transition` 必须分属性写，不得用 `transition: all`**。后者会把布局属性也纳入动画，导致悬停时出现非预期的位置抖动。全库 `transition: all` 现为 0 处。
- **焦点环用 `:focus-visible` 而非 `:focus`**。鼠标点击不显示焦点环，只有键盘导航显示。
- **危险按钮悬停变为实心红底白字**。这是有意的高对比反馈——危险操作需要明确的悬停确认，不能与其他按钮一样只做浅底变化。
- **主按钮按下不得落到普通按钮的浅蓝底**。`.btn.primary:active` 必须显式覆盖为 `--accent-hover` 深档，否则按下瞬间颜色突变。

**「插件」按钮的展开态**（同属 v0.3.4）：

- **设计**：面板展开时按钮变浅主色底 + 主色描边 + 主色文字，左侧三角箭头旋转 90°；收起恢复原样。
- **理由**：按钮点击是切换逻辑（再点一次收起），但此前展开与收起外观完全一致，用户既不知道当前是否展开，也不知道再点能收起。面板内部的关闭按钮要看到面板才知道。
- **约束**：三角箭头**必须用 `border` 绘制、`content` 留空**。用文字字符（如 `▸`）会进入按钮的可访问名称，导致 E2E 的 `getByRole("button", { name: "插件", exact: true })` 匹配失败。
- 必须补 `aria-expanded`，供读屏软件识别状态。

**变更流程**：如需改变任一维度（如恢复两套反馈、去掉按下缩放），先在此节说明理由并获得确认。只调参数值（时长、缩放比例、颜色令牌）不需要改本节。

**相关代码**：`src/styles/common.css`（`.btn` 系列与令牌定义）、`src/styles/dsplugins.css`（`.dp-btn*` / `.dp-icon-btn` / 分段控件 / 分类栏）、`src/components/InstalledList.vue`（「插件」按钮展开态）、`e2e/d22-plugin-toggle.spec.js`（展开态用例）。

### 2.12 无边框窗口标题栏（v0.3.6）

**现象**：主窗口顶部有两层标题栏——系统原生的（深色，含图标、标题、三键）与其下的应用蓝色顶栏（logo + 版本号 + 根目录）。视觉冗余，且系统标题栏的配色不跟随应用主题。

**设计**：`tauri.conf.json` 设 `decorations: false`，由应用自绘顶栏承担拖动与三键。

**理由**：

- 两层标题栏是重复信息，去掉系统层后界面更干净，且顶栏配色跟随主题。
- Windows 11 下系统标题栏与应用的浅色/暗色主题很难完全协调。

**约束（不得违反）**：

1. **拖动必须带阈值**（4px）。直接给顶栏加 `data-tauri-drag-region` 会吞掉双击，导致双击最大化失效。实现方式是 `mousedown` 后监听 `mousemove`，位移超过 4px 才调 `startDragging()`，未超阈值则放行 `dblclick`。
2. **三键的语义必须与系统一致**：最小化 / 最大化↔还原（图标随状态切换）/ 关闭。关闭按钮 hover 时红底白字。
3. **按钮文字走 i18n**，五种语言都要有。
4. **启动加载页必须能关窗**：加载页覆盖整个窗口，顶栏不可见。若启动卡住，用户没有其他出口。故加载页右上角必须有独立关闭按钮。
5. **AUMID 不得受影响**：`set_process_aumid` / `register_aumid_icons` 保持不变。管理器窗口与 dsh 内嵌窗口的任务栏图标和分组必须仍分开。
6. **不得给内嵌 dsh 窗口加边框**：那个窗口本来就无系统标题栏，由注入的 `topbar.js` 提供工具条。

**风险**：无边框窗口在 Windows 上的任务栏行为与有边框不同，改完必须实机验证图标不丢、不错误合并分组。

**相关代码**：`src-tauri/tauri.conf.json`（`decorations`）、`src/App.vue`（顶栏、拖动、三键）、`src/components/LaunchScreen.vue`（加载页拖动与关闭）、`src-tauri/src/window.rs`（AUMID，未改）。

### 2.13 内嵌 dsh 窗口标题栏（v0.3.6）

**现象**：内嵌 dsh 窗口自带系统标题栏（Windows 深色，含图标/标题/三键），与 dsh 页面本身的浅色/深色主题不协调；原 `topbar.js` 只在页面左上角画一个小圆点（hover 显示版本号胶囊，点击展开面板），信息展示弱且与系统标题栏视觉冲突。

**设计**：dsh 窗口设 `decorations: false`，由注入的 `topbar.js` 自绘整条标题栏——左侧版本号，中间 URL（可点击选中复制），右侧「重启 dsh」+ 分隔线 + 最小化/最大化/关闭三键。配色跟随 dsh 页面深浅色。

**关键约束（不得违反）**：

1. **深浅色判定只看 `body[data-ds-dark-theme]` 属性是否存在**，不得观察 `html[style]`。
   - 原因：dsh 的样式切换与 `html` 上的内联样式抢时序，观察 `html[style]` 会触发 dsh 的渲染重入，实测导致**闪退**。
   - 观察器必须加 **250ms 防抖**（dsh 切换主题时会连续触发多次 attribute mutation）。

2. **窗口控制必须走事件通道，不能直接 invoke 应用命令**。
   - 原因：内嵌 dsh 窗口是 **remote 上下文**（`http://127.0.0.1:*`），Tauri 2 对 remote 上下文默认**拒绝**应用自有命令（`log_frontend` / `restart_version` 等），报 `Command xxx not allowed by ACL`。
   - 授权插件命令（`plugin:event|emit`，由 `core:default` 覆盖）可用。故 topbar 的全部通知（日志 / 重启 / 窗口控制 / 主题变化）统一 emit 事件，Rust 侧 `listen_any` 接收处理。

3. **不得在 `build.rs` 声明 `AppManifest::commands()`**。
   - 原因：该 API 是**白名单模式**——一旦声明，未列出的命令全部失效，主界面几十个命令会集体报错。给 remote 上下文授权应用命令若必须走 ACL，应写 `src-tauri/permissions/*.toml` 权限文件，而不是 `AppManifest`。

4. **DWM 深色模式属性需回退**：Win10 20H1+ / Win11 用属性 20（`DWMWA_USE_IMMERSIVE_DARK_MODE`），更早的 Win10 用 19。实现上先试 20，返回错误再试 19（本机 Win10 19045 需 19）。

5. **关闭按钮走 `win.close()`**，由已有的 `WindowEvent::Destroyed` 回调 kill dsh 进程树——不要另写 kill 逻辑，避免与代次判定重复。

**相关代码**：`src-tauri/src/topbar.js`（自绘标题栏、主题观察）、`src-tauri/src/commands/launch.rs`（`.decorations(false)`）、`src-tauri/src/lib.rs`（`topbar-log` / `topbar-restart` / `topbar-ctrl` / `topbar-theme` 四个监听器）、`src-tauri/src/window.rs`（`set_dwm_dark`）。

**验证方式**：浅色/深色各截一张窗口图对比；三个窗口控制按钮逐个点击；`frontend.log` 应有 `[topbar] injected ... dark=true/false` 与按钮点击打点。
