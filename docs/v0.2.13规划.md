# v0.2.13 开发规划 —— 占用扫描体验优化（两段式 + 缓存）

> 编写日期：2026-10-15 · 基线：v0.2.12
> 定位：**体验优化**（不改扫描算法）。目标：把 36s/版本的干等，变成「秒出总量 + 后台补精确 + 后续秒开」。
> 分支：`feat/v0.2.13`
> 关联：[开发缺口](开发缺口.md)（P7）、[技术债清单](技术债.md)（D11）

---

## 一、背景

P7 已穷尽验证：**精确到字节的文件级共享，必须逐文件 open 读 nlink**，无捷径（NTFS 1024 上限 + 同内容可独立）。
单版本约 26000 文件 → **约 36s**；N 个版本串行 ≈ N × 36s。

**本版不改算法**，只改体验：
1. **两段式**：先秒出总量（只读 size），再后台补共享/独占（读 nlink）
2. **缓存**：汇总结果存盘，指纹未变则秒开
3. **进度反馈**：版本级 + 文件级

## 二、范围

| # | 项 | 说明 |
| :--- | :--- | :--- |
| 1 | **统一扫描按钮**（GUI） | 工具栏新增「扫描全部占用」，扫所有已安装版本 |
| 2 | **保留单版本按钮**（GUI） | 每行原有「扫描占用」保留，只扫该版本 |
| 3 | **两段式** | 第一段秒出总量；第二段后台补共享/独占，逐版本刷新 |
| 4 | **进度反馈** | 版本级（第 X/N 个）+ 文件级（本版本 Y%） |
| 5 | **结果缓存** | `<根>/cache/size-cache.json`，只存汇总（约 200B/版本） |
| 6 | **缓存失效** | 版本列表指纹 + store 指纹；不一致则重扫覆盖 |
| 7 | **CLI 体验优化** | `--info` 用缓存（命中秒开） |

**不做**：
- ❌ CLI「扫全部」命令（用户明确不要）
- ❌ 改扫描算法（nlink 仍逐文件读）
- ❌ 预打包缓存（版本太多 + 算不出 nlink）

## 三、交互设计

```
工具栏： [扫描全部占用]   ← 新增，带缓存

点「扫描全部」
  ↓ 第一段（1~3s，只读 size，不 open）
  立即显示：每版本「占用约 500MB」
  ↓ 第二段（约 N×36s，逐文件读 nlink）
  进度：「正在扫描第 3/5 个版本 · 本版本 60%」
  每算完一个版本 → 刷新该行，补「复用 480MB / 独占 20MB」
```

单版本按钮：点一次 → 扫该版本（也走两段式：秒出总量 + 后台补精确）→ 结果进缓存。

## 四、缓存设计

### 位置
```
<根目录>/cache/size-cache.json
```

### 结构
```json
{
  "version_list_fp": "<已安装版本名+修改时间的哈希>",
  "store_fp": "<store 目录/store prune 时间的哈希>",
  "generated_at": 1234567890,
  "versions": {
    "0.2.0-rc.2": { "total": 500000000, "shared_size": 480000000, "shared_count": 24000, "exclusive_size": 20000000 },
    "0.2.1-alpha.1": { "total": 510000000, "shared_size": 490000000, "shared_count": 24200, "exclusive_size": 20000000 }
  }
}
```

**只存汇总，不存逐文件清单** → 约 200 字节/版本，KB 级，不占磁盘。

### 失效
- 计算「版本列表指纹 + store 指纹」，与缓存内比对
- 一致 → 用缓存（秒开）
- 不一致 → 缓存失效，重扫并覆盖写入

### 清理
- 永远单文件、覆盖写 → 不膨胀
- 卸载版本 → 下次扫描时清掉缓存里多余条目
- 文件损坏/读失败 → 当无缓存，重扫
- 用户改根目录 → 缓存在 `<根>/cache/`，旧根缓存自然不再访问
