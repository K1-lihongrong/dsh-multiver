## 二、i18n：install_hint

**现状**：`CheckItem.install_hint` 是硬编码中文（环境检查未通过时"该怎么办"的说明）。
界面已 4 语言，但这段说明不跟随。

**方案**：
- `CheckItem` 增加 `hint_key`（如 `"env.node.hint_version"`）
- 前端：`c.hint_key ? t(c.hint_key) : c.install_hint`
- 词条表补 4 语言的 hint 文案

**边界**：
- ✅ 做 `install_hint`（固定说明文案）
- ❌ 不做 `detail`（多为版本号/路径/动态值，i18n 收益低）

**涉及文案**（`envcheck.rs`）：
- Node 版本不满足 / 特性探测失败 / 未找到 node
- pnpm 未找到
- 根目录不可写

---

## 三、CLI `--run <版本>`

**行为**（与 GUI 的「浏览器打开」一致）：
- 复用 `launcher::spawn_web_console`：**新控制台窗口** + **不传 `--no-open`**
- dsh 自动打开系统浏览器
- **关掉那个控制台窗口 = 停止服务**（原生行为，不做 detach、不做 `--stop`）

**要点**：
- 该版本必须已安装
- 与 GUI 内嵌窗口的互斥逻辑：CLI 进程独立，无法感知 GUI 窗口 → **不处理互斥**（用户自行注意）
- 端口：沿用 `spawn_web_console` 的逻辑（固定 3080，占用则提示）

---

## 四、流程改进（重要）

**前端改动后，必须用 Playwright + vite preview 渲染验证**，不能只跑 `pnpm build`。
（v0.2.7 的教训：导出按钮在 `v-if="state"` 内，构建通过但纯浏览器暴露了问题。）

---

## 五、不做

- `--stop`（`--run` 关窗口即停，无需）
- `--run` 的 detach（保持原生"关窗口即停"）
- `detail` 的 i18n
- macOS / 自动更新 C2 / CLI 子命令风格（各自单独排期）

---

## 六、验收标准

- 环境检查未通过时，切换界面语言，`install_hint` 跟随变化
- `dsh-multiver --run <版本>` 能拉起新控制台窗口 + 自动弹浏览器
- `cargo test` 全绿；前端 Playwright 验证通过；release 打包正常
