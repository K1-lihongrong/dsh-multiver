# 问题日志查看指南

> 本文面向**使用者与维护者**，说明 dsh-multiver 运行时产生的日志在哪里、各记录什么、
> 遇到问题如何用它们定位原因。
> 日志系统于 v0.1.8 后新增（阶段一：可观测性）。

---

## 一、日志位置

所有日志都在**数据根目录**的 `logs/` 子目录下：

~~~
<数据根>/logs/
├── app.log            # 主进程错误（启动失败、创建窗口失败等）
├── frontend.log       # 前端（WebView）JS 错误
├── session-<时间>-<版本>.log   # 每次「运行」版本的完整输出（最重要）
├── launch-error.log   # 精简启动（--launch-version）失败
├── maintenance.log    # 磁盘维护（清理缓存 / store prune）
└── dsh-stderr.log     # （历史遗留，可能为空）
~~~

**数据根**默认是程序（exe）所在目录；若在「路径设置」里改过「数据根目录」，则以该目录为准。
界面「路径设置」面板点 **logs** 一行，可直接在文件管理器打开该目录。

## 二、各日志记录什么

### 1. `session-<时间>-<版本>.log` —— 排查问题的第一选择

**每次点「运行」启动某个 dsh 版本**时生成一个新文件，记录这次启动的完整过程：

~~~
===== DSH 0.1.7-rc.2 session @ 20261002-073730 =====
cmd: dsh web --port 0 --no-open
env DSH_HOME=D:\...\home
env store=D:\...\store cache=... state=...
pid: 15216
[out] dsh web: http://127.0.0.1:42614/?token=...
[err] （dsh 的错误输出，如有）
~~~

- `[out]` = dsh 的**标准输出**（含启动后的访问 URL）
- `[err]` = dsh 的**错误输出**
- 文件头记录了：版本、启动命令、关键环境变量、进程 PID

**保留策略**：只保留最新 **20 份**，旧的自动删除（防无限增长）。

### 2. `app.log` —— 主进程错误

主进程（管理器本身）在关键操作失败时写入。每行格式：

~~~
[20261002-073450] [launch_window] 0.1.7-rc.2 (启动超时：90 秒内未解析到 dsh web 地址)
   ↑时间          ↑场景         ↑版本   ↑具体错误
~~~

常见场景（方括号里的值）：
- `launch_window` —— 运行版本失败（启动超时、进程提前退出、创建窗口失败）
- `open_in_browser` —— 「浏览器打开」启动失败
- `restart_version` —— 窗口内「重启」失败

### 3. `frontend.log` —— 前端 JS 错误

界面（WebView）里未捕获的 JS 异常 / Promise 拒绝会写到这里。
**界面白屏、按钮无反应**类问题先看这里。

### 4. `launch-error.log` —— 精简启动失败

通过桌面快捷方式（`--launch-version`）启动、且失败时记录。
发布版是无控制台的 GUI 程序，此文件是那条路径唯一的错误出口。

### 5. `maintenance.log` —— 维护记录

磁盘维护（清理孤立缓存、`pnpm store prune`）的成功/失败记录，正常排查用不到。

## 三、遇到问题怎么查（按现象）

| 现象 | 先看 | 找什么 |
|---|---|---|
| **点「运行」没反应 / 报错** | `session-*.log`（最新）+ `app.log` | 是否有 `[out] dsh web: http://...`；app.log 有无超时/退出记录 |
| **首次运行失败、再点就好**（已知 GAP-001） | `session-*.log` 是否**空白** + `app.log` | 冷启动超时；新版本已放宽超时到 90s |
| **界面白屏 / 按钮无反应** | `frontend.log` | JS 异常堆栈 |
| **浏览器打开失败** | `app.log` | `open_in_browser` 记录 |
| **桌面快捷方式启动失败** | `launch-error.log` | 错误文本 |
| **dsh 页面报错 / 加载异常** | `session-*.log` 的 `[err]` 行 | dsh 自身错误 |

## 四、反馈问题时请附带

1. **现象**：做了什么操作、期望什么、实际什么
2. **时间**：大概什么时候（便于在 `app.log` 里定位对应时间戳）
3. **版本**：用的是哪个 dsh 版本
4. **日志**：相关日志文件内容（尤其最新的 `session-*.log` 和 `app.log`）

> 日志里含本地路径和 dsh 访问 token（仅 127.0.0.1 本地有效），反馈时按需脱敏。

## 五、给开发者：日志实现位置

| 内容 | 代码位置 |
|---|---|
| 日志模块（时间戳/落盘/轮转） | `src-tauri/src/logging.rs` |
| 会话日志（stdout/stderr 落盘） | `src-tauri/src/launcher.rs` `spawn_web_hidden` |
| 主进程错误落盘 | `src-tauri/src/lib.rs` `log_app_error` |
| 前端错误命令 | `src-tauri/src/lib.rs` `log_frontend`；`src/App.vue` 全局捕获 |
| 维护日志 | `src-tauri/src/lib.rs` `log_maintenance` |

**设计原则**：零外部依赖、失败静默（写日志失败绝不影响主流程）、UTC 时间戳。
