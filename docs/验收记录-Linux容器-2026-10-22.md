## 3. 本次新增问题

### 3.1 离线时「npm 源连通」误报为通过（L-32，建议优先修）

- 现象：断网/死代理下 `env --json` 约 71s 后仍返回 `ok=true, detail="可达（最新 0.2.1-rc.2）"`。
- 根因：`envcheck::check_registry` 调用 `pnpm view`；pnpm 联网失败后回退到本地元数据缓存并返回成功。
- 影响：用户断网时以为源可用，随后安装在长时间等待后失败；与 L-32 的「不长时间卡死」要求冲突。
- 建议：registry 检查改为带 5~8s 超时的 HTTP 探测（如 `GET <registry>/-/ping`），或在 pnpm 调用中禁用离线回退；失败时明确提示。

### 3.2 无中文字体时界面变空白且无提示（L-09）

- 现象：字体配置中移除 CJK 后，所有中文标签/按钮变为空白，界面基本不可用。
- 建议：启动时检测 `fc-list :lang=zh`，为空则在环境检查中给出非致命提示与安装命令。

### 3.3 「浏览器打开」在无浏览器时静默失败（L-18）

- 现象：dsh 的 xdg-open 返回 3，管理器只显示「已启动」toast；控制台输出被丢弃，用户拿不到 URL。
- 建议：启动后等待首行 URL，若浏览器交接失败则 toast/对话框展示 URL；或直接由管理器调用 opener 并在失败时提示。

### 3.4 无单实例机制（L-11）

- 现象：连续启动得到两个进程/两个窗口，共享同一数据根。
- 建议：加单实例锁并聚焦已有窗口，或在文档中声明「支持多开」。

### 3.5 默认 npm 镜像落后导致安装失败（L-31）

- 现象：npmmirror 缺少 `@aws-sdk/types@^3.975.0`，默认源安装失败；官方源成功。
- 建议：安装失败分类中把「依赖版本在镜像缺失」也纳入「换源重试」入口；手册提示优先官方源或更新镜像。

### 3.6 文档：Node 版本下限应写 `>=24.2`

- 清单写「`^22.19.0` 或 `>=24`」，但 Node 24.1.0 因缺少 `import.meta.main` 被环境检查判为不满足；
  Node 22.19 / 24.2+ 才具备该特性。建议把下限写清（22.19+ 或 24.2+）。

### 6.3 本轮新观察（未改代码）

- **`ERR_PNPM_NO_VERSIONS` 未纳入「换源重试」分类**：模拟镜像完全未发布某子包时，pnpm 返回
  `ERR_PNPM_NO_VERSIONS No versions available for @aws-sdk/types`，`classify_error` 归为 `unknown`，
  GUI 只弹 toast（无换源弹窗）。该场景与「镜像未同步」同类，建议后续把 `NO_VERSIONS` 一并归入
  `incomplete-version`。本轮按要求用 `ERR_PNPM_NO_MATCHING_VERSION` 验证，路径正常。
- 浏览器模式的 dsh web 进程在管理器退出后继续运行（与设计注释一致，非残留）。
