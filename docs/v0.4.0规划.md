## 一、现状与要解决的问题

alpha.1 已经把“实例是全局实体”的数据结构做完。当前实际行为：

- 一份 `DSH_HOME` 位于 `homes/<id>`，可挂到多个版本（`version_instances`）。
- 每个版本有独立的主按钮目标（`selected_target`）；旧 `isolated_versions` 仅作镜像。
- 启动仍只认版本：`launch_window` 固定使用 `ProcKey::Shared`，路径解析传 `None`。
- CLI 只有旧 `isolate <版本> [--off]`，没有实例命令。
- GUI 仍是旧的「隔离 ▾」菜单，没有实例列表、没有主按钮下拉。

所以 v0.4.0 剩余工作不是“造模型”，而是**把已有模型暴露到 CLI、进程与 GUI**。

要解决的问题：

1. 同版本多实例无法启动：进程 key 固定为版本，第二次点「运行」只会聚焦已有窗口。
2. 实例无法通过命令行管理：创建、挂载、改名、删除都缺入口。
3. 隔离数据无法跨版本复用：数据已移到 `homes/<id>`，但 GUI 与 CLI 仍按版本理解隔离。
4. 运行态无法区分实例：`list_running_versions` 把版本号和实例 id 混在同一个数组里，前端只认单个版本字符串。

## 二、目标与不做什么

### 2.1 目标

- 实例是**全局实体**，一份 `DSH_HOME`，可挂载到任意多个已安装版本。
- 一个版本可挂载任意多个实例；不同版本看到的是**不同的子集**。
- 同版本多实例可同时启动，各自独立窗口与进程，互不干扰。
- 非隔离（共享 home / 复用官方 `~/.dsh`）保留为**版本级默认**，与实例并列。
- 既有用户的 `isolated_versions` 自动迁移，行为不变；迁移可中断重试。

### 2.2 明确不做

| 项 | 原因 |
| :--- | :--- |
| 每实例独立安装目录 | 一个版本 300MB+，多实例线性增长，与“快速对比”初衷相悖 |
| 实例级 `use_official_dsh_home` | 全局开关保持现状，不引入“每版本独立非隔离形态” |
| 同一实例多版本并发运行 | 一份 home 两个进程写有损坏风险；一个实例最多一个窗口 |
| 名称参与路径 | 目录用 `id`，名称仅作展示，规避非法字符与路径穿越 |
| 端口固定分配 | 维持 `--port 0` 随机端口 |
| WebView2 内容迁移/复制 | 升级后首次打开可能丢 cookie/偏好；只做同卷目录改名，不复制数据 |
| `clean` 自动清孤儿实例 | `clean` 只清缓存与 trash，不碰用户数据 |
| 卸载版本时顺带删实例 | 卸载只解除挂载，实例保留为孤儿 |
| Linux 打包发布（AppImage/deb） | 明确不做；发布产物仍为 Windows 单 exe，Linux 仅 CI 编译/测试 |

## 三、数据模型（`config.json`）

### 3.1 新结构

```jsonc
{
  "schema_version": 2,
  "root_dir": null,
  "default_version": null,
  "use_official_dsh_home": false,
  "broken_versions": [],
  "maintenance": { },
  "runtime_prompt_dismissed": false,

  "instances": [
    { "id": "i1", "name": "默认隔离", "created_at": 1762300000, "state": "ready" },
    { "id": "i2", "name": "对比用",   "created_at": 1762300100, "state": "ready" }
  ],
  "instance_seq": 2,
  "version_instances": {
    "0.2.1-rc.4":    ["i1", "i2"],
    "0.2.2-alpha.2": ["i2"]
  },
  "selected_target": {
    "0.2.1-rc.4": "i2",
    "0.2.2-alpha.2": null
  },

  // 只读兼容镜像：由配置层同步维护，不是唯一真相源；计划 v0.5 删除
  "isolated_versions": ["0.2.1-rc.4"]
}
```

### 3.2 字段规则

| 字段 | 规则 |
| :--- | :--- |
| `schema_version` | 当前为 2；缺失按 1 处理并迁移 |
| `instances[].id` | `i` + 全局自增序号（`i1`/`i2`…），**永不复用** |
| `instance_seq` | `u64`；新建时 `checked_add`，生成的 id 若已存在则继续递增 |
| `instances[].name` | 非空、trim、禁控制字符、禁 `/` `\\`、≤32 **Unicode 字符**、**全局唯一（不区分大小写）** |
| `instances[].created_at` | Unix 秒，仅作展示与排序 |
| `instances[].state` | `ready` / `deleting`；`deleting` 由启动续删清理 |
| `version_instances` | key 为已安装版本；value 为实例 id 数组，顺序即展示顺序 |
| `selected_target` | key 为版本；value 为实例 id 或 null；存 **id 不存名称** |
| `isolated_versions` | **只读镜像**：`ensure_default_instance` / `detach_version` / 迁移负责同步；读取点逐步切到 `version_instances` |

**`selected_target` 语义**：显式实例 > `selected_target` 的显式值 > 共享/官方默认。缺失与 null 等价，均不使用“第一个挂载实例”的隐式推断。

## 四、迁移

`Config::load_checked` 在 `schema_version < 2` 时调用 `migrate_v0_4_0()`：

1. 对齐 `instance_seq` 与已有实例的最大序号。
2. 遍历 `isolated_versions`；已有挂载的版本跳过。
3. 为每个版本分配 id 与唯一名称（「默认隔离」）。
4. 目录：`versions/<版本>/home` → `homes/<id>`：
   - 目标不存在、源存在：同卷 `rename`；失败则复制后删源。
   - 目标存在：**复用目标**，写 `app.log`；源仍存在时**不删源**，日志给出两个路径。
   - 都不存在：`create_dir_all`。
5. 写入实例、`version_instances`、`selected_target`；`isolated_versions` 镜像保留，不清空。
6. `schema_version = 2`，写迁移日志。

**幂等与中断**：

| 中断点 | 下次启动 |
| :--- | :--- |
| 改名完成、config 未保存 | 重新分配到同一 id，复用 `homes/<id>`，不阻塞升级 |
| config 已保存、目录缺失 | 首次运行时 `resolve_home_ref` 创建空目录 |
| 源目录与目标同时存在 | 保留两者，日志提示人工确认 |

迁移**不删除任何用户数据**；迁移失败保留原 `config.json`。

## 五、路径解析

`paths.rs` 现有三个入口：

```rust
pub(crate) fn resolve_home(cfg: &Config, dirs: &Dirs, version: &str) -> PathBuf;
pub(crate) fn resolve_home_for(
    cfg: &Config,
    dirs: &Dirs,
    version: &VersionId,
    instance: Option<&InstanceId>,
) -> PathBuf;
pub(crate) fn resolve_home_ref(dirs: &Dirs, home_ref: &HomeRef) -> PathBuf;
```

解析顺序：

1. 显式实例 `Some(id)` → `homes/<id>/`（`create_dir_all`）
2. `selected_target[版本] = Some(id)` → `homes/<id>/`
3. `selected_target[版本] = None` / 缺失 → 官方 `~/.dsh`（开关开）或 `<根>/home`

**校验要求**：CLI 接受 `--instance` 时必须先确认该 id 在 `instances` 中存在且已挂载到目标版本；当前 `resolve_home_for` 不校验，M2 在命令层补。

调用点（生产代码 **20 处**，测试另计）：

| 文件 | 数量 | 说明 |
| :--- | ---: | :--- |
| `commands/launch.rs` | 3 | 启动、重启、控制台 |
| `commands/isolated.rs` | 3 | 复制/清理/打开目录 |
| `commands/plugins.rs` | 7 | 插件操作 |
| `cli/commands/misc.rs` | 4 | copy-shared / clear-isolated 等 |
| `commands/scan.rs` | 1 | 占用扫描 |
| `cli/commands/version.rs` | 1 | `info` |
| `paths.rs` | 1 | 转发脚本 |

M2 起涉及实例目标的路径改用 `resolve_home_for`；其余保留 `resolve_home` 取版本默认目标。

## 六、进程与窗口

### 6.1 ProcKey

```rust
pub enum ProcKey {
    Shared(VersionId),      // 非隔离窗口按版本区分
    Instance(InstanceId),   // 实例窗口按 id 区分，不含版本
}
```

- 非隔离窗口：不同版本各一个进程。
- 实例窗口：同一实例在哪个版本先启动就在哪跑；其他版本显示「运行中（X）」。
- 现状：`ProcKey::instance` 仍是 `#[allow(dead_code)]`，`launch_window` 固定 `ProcKey::Shared`；M3 接线。

### 6.2 窗口 label

`window_label_gen(&proc_key, generation)`。label 含实例 id，天然不冲突。

### 6.3 WebView2 数据目录

- 非隔离：`webview/<版本>/_shared`
- 实例：`webview/<版本>/<实例id>`

升级处理：若旧 `webview/<版本>` 存在且 `_shared` 不存在，M3 做一次同卷 rename 为 `_shared`；失败则保留旧目录并写日志，首次打开接受 cookie/偏好丢失。

### 6.4 运行态查询（新增契约）

现有 `list_running_versions() -> Vec<String>` 把版本号与实例 id 混在一起，前端无法区分。M3 新增：

```rust
pub struct RunningTarget {
    pub kind: String,          // "shared" | "instance"
    pub version: String,       // 启动该窗口的版本
    pub instance: Option<String>,
}
pub fn list_running_targets(...) -> Vec<RunningTarget>;
```

- `list_running_versions` 暂时保留；M3 改为只返回 `Shared` 的版本号，避免实例 id 混入。
- 前端运行态从单个 `runningVersion` 改为按 `(version, instance)` 的映射。

### 6.5 kill 语义与清理

- 关窗、`restart_version`、崩溃检测线程全部按 `ProcKey` 查找；**关 A 不影响 B**。
- `maintenance::cleanup_orphan_webviews` 两级判定：
  - 版本目录不存在 → 整个 `webview/<版本>` 清。
  - 版本存在 → 只清不再挂载的 `<版本>/<实例id>` 子目录；`_shared` 保留。
- 删除实例前必须确认其 `ProcKey::Instance` 不在 `ProcMap` 中。

### 6.6 窗口标题

- 非隔离：`DSH <版本>`
- 实例：`DSH <版本> · <实例名>`

## 七、CLI

### 7.1 命令表

```bash
# 兼容：不带选项 = 幂等确保（已挂载则保留选择，未挂载则建「默认隔离」并挂载）
isolate <版本>
isolate <版本> --off

# 实例本体
instance create --name <名称> --attach <版本> [--attach <版本>...]
instance list [--json]
instance rename <id> <新名>
instance remove <id>

# 版本 ↔ 实例
isolate <版本> --list [--json]
isolate <版本> --attach <id>
isolate <版本> --detach <id>

# 运行与数据
run <版本> [--instance <id>]
copy-shared <版本> --instance <id>
clear-isolated <版本> --instance <id>
```

语义：

- `isolate <版本>` = 幂等确保：已挂载则保留挂载与**显式主按钮目标**；主按钮为共享时改为指向首实例；未挂载则建「默认隔离」并挂载。`--off` = `detach_version`，不删目录。
- `instance create` 校验名称规则与全局唯一；id 由 `instance_seq` 分配；**不创建目录**，首次运行创建。
- `instance remove` 运行中拒绝；先置 `state=deleting`、保存，再 rename 到 trash，再清配置。
- `run --instance` 校验实例存在且挂在该版本；否则报错，不静默回落。
- `copy-shared` / `clear-isolated` 带 `--instance` 时必须指定已挂载实例；不带时沿用版本默认目标。

### 7.2 JSON 输出

```json
{
  "version": "0.2.1-rc.4",
  "isolated": true,
  "selected_target": "i2",
  "instances": [
    { "id": "i1", "name": "默认隔离", "home": ".../homes/i1", "size": 12345, "running_on": null },
    { "id": "i2", "name": "对比用",   "home": ".../homes/i2", "size": 6789,  "running_on": "0.2.1-rc.4" }
  ]
}
```

`isolated` 仅由镜像派生，供旧脚本兼容；新脚本以 `instances` 为准。

### 7.3 解析器与帮助

- `parse.rs` 手写线性匹配，新增带值修饰符：`--name` / `--attach` / `--detach` / `--instance`。
- `CliCommand::Isolate { version, on }` → `Isolate { version, action: IsolateAction }`，新增 `Instance { action }`。
- `help.rs` 补命令与示例；`--json` 保持唯一机读出口。

### 7.4 转发脚本

`actions::regenerate_forward_script`：版本有实例时指向首实例（`version_instances[版本][0]`）；无实例时按共享/官方。脚本注释说明可用 `run --instance` 绕过。

### 7.5 备份与导入

- 导出快照必须包含 `instances` / `version_instances` / `selected_target` / `instance_seq`；只导 `isolated_versions` 会丢挂载关系。
- 导入新快照：整体恢复上述四张表。
- 导入旧快照（只有 `isolated_versions`）：按迁移逻辑为每个版本建「默认隔离」实例并挂载；预览阶段列出将生成的实例数。
- 当前 `backup.rs` 只比较/应用 `isolated_versions`，M2 补齐。

- 卸载版本后，其独占实例仍在这里可见（孤儿）

### 8.4 跨版本运行状态

实例 A 在版本 X 运行中，切到版本 Y 的浮层：A 行显示「运行中（X）」+「聚焦」按钮，行内灰字「运行于 X」，**不提供**换版本重启入口。依赖 §6.4 的 `RunningTarget`。

### 8.5 列表数据契约

版本行需要区分「有实例但主按钮指向共享」与「没有任何实例」，现有 `VersionInfo.isolated` 只由镜像派生，信息不足。M3 增加查询（二选一）：

- 扩展 `VersionInfo`：`instance_count` + `selected_target`；或
- 新增 `list_version_instances(version) -> { instances, selected_target }`，M4 渲染浮层时调用。

推荐后者：浮层本来就需要实例列表与运行状态，避免 `list_versions` 变重。

### 8.6 i18n

当前支持五种界面语言（`zh-CN` / `zh-TW` / `en-US` / `ja-JP` / `ko-KR`）。新增约 12 个 key，五种语言同步；`check-i18n.mjs` 必须通过。

## 九、交互约束

| 约束 | 说明 |
| :--- | :--- |
| 一个实例最多一个窗口/进程 | 重复点击「运行」= 聚焦已有窗口 |
| 选中与运行解耦 | 改 `selected_target` 不影响已运行窗口 |
| 运行中可改名 | 只改 config 显示名，不动目录 |
| 运行中可解除挂载 | 只影响下次能否从该版本启动，不断进程 |
| 运行中不可删除 | 需先关窗（避免文件占用与写冲突） |
| 解除挂载即清 `selected_target` | 主按钮回落「运行」 |
| 删除实例走 trash 中转 | `rename` 到 `trash/` 瞬时返回，后台清理；失败则直接删 |
| 删除顺序 | 先置 `state=deleting` 并保存 → rename 目录 → 删 config 记录与挂载 → 清 `selected_target` → 再保存 |
| 卸载版本 | 自动解除该版本关联，**保留实例为孤儿**；不删 `homes/<id>` |
| 创建实例不建目录 | 首次运行由 `resolve_home_ref` 创建 |
| 目录已存在不报错 | `create_dir_all` 复用，不删不清空，`app.log` 留痕 |

## 十三、完成标准

1. `instance create --name A --attach X --attach Y` 成功；重复名称报错并提示挂载已有实例。
2. `isolate X --list` 正确列出 X 挂载的实例（不含 Y 的）。
3. 同版本开两个实例窗口，数据互不可见；关一个，另一个存活。
4. 同一实例在 X 运行后，Y 的浮层显示「运行中（X）」+ 聚焦按钮。
5. 旧 `config.json`（`isolated_versions: ["0.1.7"]`）升级后 home 路径与升级前等价，主按钮指向该实例；迁移中断可重试。
6. 非隔离版本仍可用共享 home 或官方 `~/.dsh`；`selected_target` 缺失时回共享 home。
7. 卸载版本后实例保留为孤儿，全局面板可见、可删；删除走 trash 中转。
8. `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test --lib`（≥271）、`pnpm build`、`node scripts/check-i18n.mjs` 全绿；E2E 71 passed（含多实例用例）。
9. Linux 只跑 CI 编译/测试，**不打包、不发布**。
