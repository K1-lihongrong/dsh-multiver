## 一、要解决的问题

当前「数据隔离」是**版本的布尔属性**：`config.json` 里 `isolated_versions: Vec<String>`，版本号在列表里 = 隔离。

由此产生的限制：

1. **一个版本最多一个隔离环境**。路径硬编码为 `<根>/versions/<版本>/home`，`resolve_home` 里没有实例维度（`paths.rs:124-137`）。
2. **同版本无法多开对比**。`launch_window` 以版本号为 key 做幂等聚焦（`launch.rs:23-35`），第二次点「运行」只是聚焦已有窗口。
3. **隔离数据无法跨版本复用**。隔离 home 绑死在单个版本目录下，想用同一批会话数据跑两个版本的代码，只能手工复制目录。

用户诉求：同一份数据（会话/凭据/插件配置）挂到多个 dsh 版本下，各自开窗口对比行为；同一版本下也可有多个互相独立的隔离环境。

## 二、目标与不做什么

### 2.1 目标

- 实例是**全局实体**，一份 `DSH_HOME`，可挂载到任意多个已安装版本。
- 一个版本可挂载任意多个实例；不同版本看到的是**不同的子集**。
- 同版本多实例可同时启动，各自独立窗口与进程，互不干扰。
- 非隔离（共享 home / 复用官方 `~/.dsh`）保留为**版本级默认**，与实例并列。
- 既有用户的 `isolated_versions` 自动迁移，行为不变。

### 2.2 明确不做

| 项 | 原因 |
| :--- | :--- |
| 每实例独立安装目录 | 一个版本 300MB+，多实例线性增长，与"快速对比"初衷相悖 |
| 实例级 `use_official_dsh_home` | 全局开关保持现状，不引入"每版本独立非隔离形态" |
| 同一实例多版本并发运行 | 一份 home 两个进程写有损坏风险；一个实例最多一个窗口 |
| 名称参与路径 | 目录用 `id`，名称仅作展示，规避非法字符与路径穿越 |
| 端口固定分配 | 维持 `--port 0` 随机端口 |
| WebView2 数据迁移 | 升级后非隔离窗口首次打开丢 cookie/偏好；dsh token 每次重生成，无实质影响 |
| `clean` 自动清孤儿实例 | `clean` 只清缓存与 trash，不碰用户数据 |

## 三、数据模型（`config.json`）

### 3.1 新结构

```jsonc
{
  "root_dir": null,
  "default_version": null,
  "use_official_dsh_home": false,
  "broken_versions": [],
  "maintenance": { },
  "runtime_prompt_dismissed": false,

  // 新增：全局实例表
  "instances": [
    { "id": "i1", "name": "默认隔离", "created_at": 1762300000 },
    { "id": "i2", "name": "对比用",   "created_at": 1762300100 }
  ],
  // 新增：id 分配计数器（历史最大，永不复用）
  "instance_seq": 2,
  // 新增：版本 → 挂载的实例 id 列表（顺序即浮层展示顺序）
  "version_instances": {
    "0.2.1-rc.4":    ["i1", "i2"],
    "0.2.2-alpha.2": ["i2"]
  },
  // 新增：每版本主按钮目标（缺失或 null = 共享 home）
  "selected_target": {
    "0.2.1-rc.4": "i2"
  },

  // 旧字段：仅迁移读取，迁移后写空数组，不参与任何逻辑
  "isolated_versions": []
}
```

### 3.2 字段规则

| 字段 | 规则 |
| :--- | :--- |
| `instances[].id` | `i` + 全局自增序号（`i1`/`i2`…），**永不复用**（删了 i2，下一个是 i3） |
| `instance_seq` | `u64`，新建时 `checked_add`；生成的 id 若已在 `instances` 中则继续递增（兜底手工改坏配置） |
| `instances[].name` | 非空、trim、禁控制字符、禁 `/` `\\`、≤32 **Unicode 字符**、**全局唯一（不区分大小写）** |
| `instances[].created_at` | Unix 秒，仅作展示与排序 |
| `version_instances` | key 为已安装版本；value 为实例 id 数组，顺序即展示顺序；解除挂载即从数组移除 |
| `selected_target` | key 为版本；value 为实例 id 或 null；存 **id 不存名称**（改名不悬空） |

### 3.3 目录布局

```
<根>/
├── versions/<版本>/              # 安装目录，所有实例共享（不变）
├── homes/<实例id>/               # 新增：实例的 DSH_HOME（全局，不分版本）
├── home/                         # 管理器共享 home（非隔离，不变）
├── webview/<版本>/_shared/       # 非隔离窗口的 WebView2 数据（变更）
├── webview/<版本>/<实例id>/      # 实例窗口的 WebView2 数据（新增）
└── trash/instance-<id>-<时间戳>/ # 删除实例时的中转目录
```

## 四、迁移

`Config::load_checked` 之后调用 `migrate_v0_4_0()`：

1. 若 `isolated_versions` 非空：
   - 按版本顺序，为每个版本建实例 `{ id: iN, name: "默认隔离", created_at: now }`
   - `version_instances[版本] = [iN]`
   - `selected_target[版本] = iN`（升级后主按钮仍指向隔离环境，行为不变）
   - 目录：`versions/<版本>/home` → `homes/iN`（`rename` 瞬时；失败则复制后删）
2. `instance_seq` = 已分配的最大序号
3. `isolated_versions` 写空数组
4. 写 `logs/app.log` 一行记录迁移结果（版本数、生成的 id）

**幂等**：`isolated_versions` 为空时直接跳过，不产生任何副作用。

## 五、路径解析

`paths.rs::resolve_home` 签名变更：

```rust
pub(crate) fn resolve_home(
    cfg: &Config,
    dirs: &Dirs,
    version: &str,
    instance: Option<&str>,   // None = 非隔离（版本级默认）
) -> PathBuf
```

解析顺序：

1. `instance = Some(id)` 且该实例存在 → `homes/<id>/`（`create_dir_all`）
2. `instance = None` 且 `use_official_dsh_home` → `~/.dsh`
3. `instance = None` → `<根>/home`

**实例路径与非隔离彻底解耦**：一个版本可以既有 3 个实例，又用共享 home 跑一个非隔离窗口。

调用点（共 8 处）：`launch.rs`×3、`cli/commands/misc.rs`、`cli/commands/version.rs`、`commands/plugins.rs`×5、`paths.rs` 自身。

`versions/isolated.rs::isolated_home` → `instance_home(versions_dir_or_root, id)`。

## 六、进程与窗口

### 6.1 ProcMap key

```rust
pub(crate) fn proc_key(version: &str, instance: Option<&str>) -> String
// 非隔离 → "@shared:<版本>"
// 实例   → "@inst:<id>"
```

- 非隔离窗口按版本区分（不同版本的非隔离开两个独立进程）
- 实例窗口按 id 区分，**不含版本**——同一实例在哪个版本先启动就在哪跑，其他版本显示「运行中（X）」

### 6.2 窗口 label

`window_label_gen(&proc_key, generation)`。label 含实例 id，天然不冲突。

### 6.3 WebView2 数据目录

- 非隔离：`dirs.webview.join(version).join("_shared")`
- 实例：`dirs.webview.join(version).join(id)`

### 6.4 kill 语义

关窗回调、`restart_version`、崩溃检测线程全部按 `proc_key` 查找。**关 A 的窗口不影响 B**。

`maintenance.rs::cleanup_orphan_webviews` 判定改为两级：`<版本>/_shared` 与 `<版本>/<实例id>` 均需对应存在。

## 七、CLI

### 7.1 命令表

```bash
# 兼容：不带选项 = 幂等确保（已挂载则不动，未挂载则建「默认隔离」并挂载）
isolate <版本>

# 实例本体
instance create --name <名称> --attach <版本> [--attach <版本>...]
instance list [--json]
instance rename <id> <新名>
instance remove <id> [--force]

# 版本 ↔ 实例
isolate <版本> --list [--json]
isolate <版本> --attach <id>
isolate <版本> --detach <id>
isolate <版本> --off            # 解除该版本与全部实例的关联，不删任何目录

# 运行与数据
run <版本> [--instance <id>]
copy-shared <版本> --instance <id>
clear-isolated <版本> --instance <id>
```

### 7.2 `--json` 输出

```json
{
  "version": "0.2.1-rc.4",
  "isolated": true,
  "selected_target": "i2",
  "instances": [
    { "id": "i1", "name": "默认隔离", "home": ".../homes/i1", "size": 12345, "running_on": null },
    { "id": "i2", "name": "对比用",   "home": ".../homes/i2", "size": 6789,  "running_on": "0.2.1-rc.4" }
  ]
}
```

### 7.3 解析器改动

`parse.rs` 是手写线性匹配，新增带值修饰符须扩展 `parse.rs:39-57` 的 while 循环：`--name` / `--attach` / `--detach` / `--instance` / `--remove` / `--rename`。

`CliCommand::Isolate { version, on }` → `Isolate { version, action: IsolateAction }`，新增 `CliCommand::Instance { action }`。

### 7.4 转发脚本

`actions.rs::regenerate_forward_script`：版本有实例时指向首实例（`version_instances[版本][0]`）；无实例时按现状走共享/官方。脚本内注释说明可用 `run --instance` 绕过。

## 八、GUI

### 8.1 版本行

- 主按钮「运行」+ 右侧小三角下拉：`非隔离（默认）` / 各挂载实例 / `＋ 新建实例…`
- 主按钮文案随 `selected_target` 变化：「运行」/「运行 实例 A」/「聚焦 实例 A」
- 「隔离 ▾」**保留原名**（不是「实例 ▾」），仅已隔离版本显示

### 8.2 「隔离 ▾」浮层（popover，点击外部关闭）

```
┌─ 0.2.1-rc.4 ────────────────────────────┐

```

- 共享 home 行名称按 `use_official_dsh_home` 动态显示「共享 home（管理器）」或「共享 home（官方 ~/.dsh）」
- 单选框选中行 → 主按钮目标，持久化到 `selected_target`
- 选中目标失效（实例被删/解除挂载）→ **静默回落**共享 home，不弹提示
- 全局运行实例数 > 3 时浮层顶部一行温和提示（不阻止）

### 8.3 全局实例面板

「扫描全局占用」旁新增「实例管理」按钮，孤儿数量以角标显示。

- 列出**全部实例**，孤儿（`version_instances` 中无任何版本引用）置顶并标「未挂载」
- 每行：名称、home 路径、占用、挂载版本列表、运行状态
- 操作：运行（多挂载时弹菜单选版本，单挂载直接运行）、打开目录、改名、挂载/解除挂载（已安装版本多选，勾选即时保存）、删除
- 运行中实例：删除按钮禁用并提示「请先关闭其窗口」；改名与解除挂载允许

### 8.4 窗口标题

- 非隔离：`DSH <版本>`
- 实例：`DSH <版本> · <实例名>`

### 8.5 运行状态跨版本展示

实例 A 在版本 X 运行中，切到版本 Y 的浮层：A 行显示「运行中（X）」+「聚焦」按钮（可点，切到 X 的窗口），行内灰字「运行于 X」，**不提供**换版本重启入口。

## 九、交互约束

| 约束 | 说明 |
| :--- | :--- |
| 一个实例最多一个窗口/进程 | 重复点击「运行」= 聚焦已有窗口 |
| 选中与运行解耦 | 改 `selected_target` 不影响已运行窗口 |
| 运行中可改名 | 只改 config 显示名，不动目录 |
| 运行中可解除挂载 | 只影响下次能否从该版本启动，不断进程 |
| 运行中不可删除 | 需先关窗（避免文件占用与写冲突） |
| 解除挂载即清 `selected_target` | 主按钮回落「运行」 |
| 删除实例走 trash 中转 | `rename` 到 `trash/` 瞬时返回，后台清理；失败则直接删 |
| 删除顺序 | 先 rename 目录 → 删 config 记录与挂载 → 清 `selected_target` → 保存 config |
| 卸载版本 | 自动解除该版本关联，不删实例本体；孤儿保留并在面板标「未挂载」 |
| 创建实例不建目录 | 首次运行由 `resolve_home` 创建 |
| 目录已存在不报错 | `create_dir_all` 复用，不删不清空，`app.log` 留痕 |

## 十二、风险

| 风险 | 应对 |
| :--- | :--- |
| **M3 关窗误杀其他实例** | 按 `proc_key` 查找；实机验证"关 A 验 B"为必过项 |
| 迁移 rename 失败（跨卷等） | 退回复制后删；失败写 `app.log` 并保留原目录 |
| 实例名含 emoji/特殊字符 | 名称不参与路径，仅展示；路径统一用 `id` |
| 手工改坏 `config.json`（`instance_seq` 回退） | 新建时校验 id 不冲突，冲突则继续递增 |
| 孤儿实例长期占磁盘 | 全局面板角标提示；`clean` 不自动删（用户数据） |
| 一个版本挂大量实例导致浮层过长 | 超过 6 个时浮层内部滚动 |

## 十三、完成标准

1. `instance create --name A --attach X --attach Y` 成功；重复名称报错并提示挂载已有实例
2. `isolate X --list` 正确列出 X 挂载的实例（不含 Y 的）
3. 同版本开两个实例窗口，数据互不可见；关一个，另一个存活
4. 同一实例在 X 运行后，Y 的浮层显示「运行中（X）」+ 聚焦按钮
5. 旧 `config.json`（`isolated_versions: ["0.1.7"]`）升级后，`0.1.7` 的 home 路径与升级前等价，主按钮指向该实例
6. 非隔离版本仍可用共享 home 或官方 `~/.dsh`
7. `cargo test` 全绿；E2E 新增多开用例通过
8. 卸载版本后实例保留为孤儿，全局面板可见可删
